# SLIDE POP! ― ゲームデザインドキュメント

## 1. コンセプト

**「滑らせて、同色をぶつける」**

ブロックは押せば壁にぶつかるまで一直線に滑る。同じ色のブロック同士が触れれば弾けて消える。重力も連鎖もない。**盤面にある色つきのブロックは1組（2個）だけで、その2個をぶつけたらクリア**です。

やることはそれだけなのに、簡単ではありません。**盤面のほとんどは灰色のブロック**で、灰色は何と触れても消えないからです。色つきの2個は灰色に阻まれて、まっすぐには近づけない。**灰色を押しのけて道を作り、そこを通して運ぶ** ―― それがこのゲームの中身です。

灰色も押せば同じように滑ります。つまり壁でありながら、**自分で並べ替えられる壁**。1個ずらせば通路が開き、同時にどこか別の通路が塞がる。

だから遊びの中身はこうなる ―― **「ここへ滑らせると、次にどこへ滑れるようになるか」を、ぶつけられる場所にたどり着くまで頭の中で辿る。** 目の前に「消える手」が無いからこそ、読むしかない。いちばん上のレベルでは、**300手ぶんそれを積み上げます**。

そして表示している手数は**厳密な最短手数**です。「解ける手順が1本ある」ではなく、**それより短い解き方は存在しない**ことまで確かめてあります。

## 2. ゲーム概要

| 項目 | 内容 |
|---|---|
| ジャンル | 空間パズル（スライド×接触消去） |
| 盤面 | 4×4 〜 8×8グリッド（広さは難易度ではなく見た目の変化） |
| ブロック | 1×2 〜 3×3 の長方形、全向き。**この形だけ**（灰色の1×2は少なめに寄せる） |
| カラー | 色つきは常に1組（2個）。色そのものはレベル番号から手続き的に作る |
| 灰色ブロック | どの色とも消えない邪魔者。盤面の大半がこれ |
| 初期配置 | 空きマスは 2〜6 マスだけ（埋め率 85〜95%） |
| 初期条件 | 色つき2個は隣接していない／**初手に消せる手がひとつも無い**／必ず全消し可能 |
| 1プレイ | 2〜300手。**これは推定ではなく厳密な最短手数**で、これより短い解き方は存在しない |
| 進行 | レベル1から上限なし。同じレベルはどの端末でも同じ譜面。**鍵は無く、どのレベルにもいつでも入れる** |
| 評価 | **手数**による星3段階（最短ちょうど／1.5倍+2手以内／クリア） |
| 情報 | 完全情報・初期配置以降ランダムなし |

### レベル進行

レベルは **1 から上限なく**続きます。難しさを表す数はひとつだけ ―― **厳密な最短手数（PAR）** です。

| レベル | 最短手数 |
|---|---|
| 1 | 2 |
| 20 | 20 |
| 50 | 40 |
| 100 | 80 |
| 500 | 100 |
| 800 | 122 |
| 900 | 143 |
| 950 | 162 |
| 1000 | **300** |

この折れ線（`src/levels.js` の `PAR_ANCHORS`）が目標で、**その手数になる盤面を探して**割り当てています。1000 レベルぶんを焼き込んであり、その先はいちばん上の 200 レベルを繰り返します（頭に戻すと難易度が一気に落ちて「終わった」感じになるため）。

前半は一気に、中盤はゆっくり、そして**最後の50レベルで跳ね上がります**。

上端を切り立たせているのは、深い盤面の出方がそうなっているからです。全探索で「ゴールから300手」の盤面が出ることは実際にありますが、4コアを回して**1時間に2枚**ほどしか採れません（110手級なら毎分2枚）。数百レベルぶんは揃いませんが、数十レベルぶんなら揃う。

この折れ線は**採れた深さの実測に合わせてあります**。願望で引いても、そこに置く盤面が無ければ意味がない ―― 上端の形は探索の当たり方がそのまま決めています。

レベル975〜1000 は 192手から 300手へ、1レベルごとに4手以上。この帯は**どのレベルも手数が違い、盤面も全部別物**です。

盤面まわりは手数から逆算されるのではなく、**手数を出せた盤面がそのまま採用される**という順序です。

| | 範囲 |
|---|---|
| 盤面 | 4×4 〜 8×8。**広いほど難しいわけではない** |
| 空きマス | 2〜6 マス。ブロックがぎっしりで、動かせる方向自体が少ない |
| ブロック | 色つきも灰色も 1×2 〜 3×3 の長方形 |
| 色つき | 常に 1 組（2 個）。残りは全部灰色 |

入門レベルにも「1手ずらせば届く」形は置いていません。見つけて押すだけで終わってしまい、読む余地が生まれないからです。**レベル1 でも 2 手**、レベル1000 では 300 手ぶん滑らせ続けます。

### 深い手数はどこにあるか ― 空きマス 3 の 6×6

「広い盤面ほど難しい」は成り立ちません。実測（1 分あたりの探索で到達した最大手数）：

| 盤面 | 空きマス | 到達した最大手数 | 110 手以上に届いた回数 |
|---|---|---|---|
| 5×5 | 2 | 36 | 0 |
| 5×5 | 3 | 81 | 0 |
| 6×6 | 2 | 65 | 0 |
| **6×6** | **3** | **156** | **4** |
| 6×6 | 4 | 115 | 1 |
| 7×7 | 3 | 139 | 2 |

**両側から挟まれた狭い谷にしか、深い盤面はありません。**

- 空きが多い → 配置が広がりすぎて全探索が終わらない。そして**手数も伸びない**（ブロックが遠回りできてしまう）
- 空きが少ない → ブロックが動けなくなり、手数が落ちる

華容道（5×4・空き 2 マス）が 81 手かかるのと同じ構造です。**深い手数は「動かせる隙間が数マスしか無い」ときにしか出ません。** 盤面を広げるのは、難しくするためではなく**見た目の変化のため**と割り切っています。

### 用語の定義

- **ブロック（ピース）**：1×2 〜 3×3 の長方形の剛体。移動・消去の最小単位
- **ペア**：同じ色のブロック2個。盤面には**1組だけ**置かれる
- **灰色ブロック**：どの色とも消えない邪魔者。数と形が「通路の迷路」を決める
- **PAR（最短手数）**：その盤面を解くのに最低限必要な手数。**推定ではなく全探索で出した厳密値**
- **追い込み手**：ペアの一方を「ぶつけられる場所」まで運ぶ、何も消さない手。色つきは1組しかないので、**最後の1手を除く全部が追い込み手**
- **仕込み手**：消したいブロックとは関係のない灰色を先に退かす手。通さないと後の手が成立しない
- **セル（マス）**：盤面の1区画
- **スライド**：ブロックが上下左右のいずれかに、障害物にぶつかるまで一直線に移動すること
- **接触**：異なるブロックのセルが上下左右で隣り合うこと（斜めは含まない）
- **通路**：ブロックが滑って通れる空きマスの連なり

## 3. ルールの三本柱

### ① スライド ― 「距離は選べない」

プレイヤーができる操作は**「どのブロックを、どの方向に押すか」**の二択だけです。押されたブロックは、壁か他のブロックにぶつかるまで滑り続けます。1マスで止めることも、手前で止めることもできません。

この**「距離の制御不能性」**が設計の要です。

- 全ての手が**決定的**になる。運も隠し情報もない
- 「押す前に、どこで止まるかを読む」ことがそのままゲームになる
- 1手1手の結果が盤面全体に波及するため、読みが深い

スライドはブロック単位（剛体）で行われます。I字型が縦に滑るとき、4セルすべてが同時に移動し、いずれか1セルでも障害物に触れれば全体が止まります。自分の元いたセルは通過可能です（自分が退いた後なので）。

### ② 同色接触消去 ― 「触れた瞬間、消える」

ブロックが滑り終えた直後、盤面が走査されます。上下左右で同じ色のブロックが触れ合っていれば、**その2個が即座に消去**されます。列を揃える必要はありません。色が触れれば、それで終わりです。

重要な細則として、**消去の単位は「ブロック」であり、単体のブロックは自己消去しません**。1つの長方形はセルが何個あっても「1つの塊」として扱われます。消去が発生するのは、**2つのブロックが接触したとき**だけです。この一点が、ゲームの成立そのものを支えています（セル単位なら初期盤面が瞬時に全滅するため）。

色つきは盤面にちょうど2個しかないので、**消去は1ゲームに1回、最後の1手でだけ起きます**。それが勝利条件そのものです。灰色はいくつ触れ合っても消えません。

### ③ 重力なし ― 「空きマスは、増えない」

消去されても、他のブロックは落下しません。すべてがその場にとどまります。

以前の多色版では、ここは「消すたびに通路が生まれ、盤面が徐々に解けていく」という設計でした。**いまは違います。** 消えるのは色つき1組だけで、しかもそれが消えた瞬間がクリアなので、**プレイ中に空きマスが増えることは一度もありません**。

つまり盤面は**最初から最後まで、同じ数の空きマスしか持たない**。68〜92%が埋まった盤面で、残ったわずかな隙間だけを使って、色つきを運びきることになります。

- 消去は最後の1手にしか起きない（自動連鎖ゼロ）
- 空きマスは増えも減りもしない。**与えられた隙間が、最初から最後まで唯一の資源**
- 盤面の形を変えられる唯一の手段は、**ブロック自体を並べ替えること**

「消して道を開ける」ができない以上、道は**押しのけて作る**しかない。ここが本作固有の手触りです。

## 4. 勝敗条件と評価

- **勝利**：色つきの2個をぶつける（灰色は最後まで盤面に残ります）
- **敗北条件は無い**

初期の設計には「どう動かしても同色接触を作れない＝デッドロック」という敗北条件がありました。これは**廃止しています**。いまの設計では、**消せる手が無いのが通常の局面**です ―― 300手のレベルなら、299手ぶんは消せる手がありません。「いま消せない」ことは詰みではなく、**通路を作るところから始めろという合図**。敗北を宣言する代わりに、`戻す`と`やり直す`をいつでも使えるようにしています。

### 星 ― 何手で解いたかで決まる

| 星 | 条件 |
|---|---|
| ★★★ | **最短ちょうど** |
| ★★ | 最短の 1.5倍 + 2手まで |
| ★ | クリア |

目安は `20 + PAR×9 + 盤面の一辺×4` 秒。L1で0:54、L1000で45:44前後です。ゲーム画面のタイムは★★★を過ぎると黄、★★も過ぎると赤に変わり、**いま星いくつぶんの位置にいるか**が常に分かります。

silver に +2 の余裕を足してあるのは、2手のレベルで1手ずれただけで ★1 まで落ちるのを避けるためです。短い問題ほど、1手の重みが大きくなりすぎる。

いま星いくつぶんの位置にいるかは、画面上の**手数**の色で分かります（★★★ を過ぎると黄、★★ も過ぎると赤）。

**一度は時間で測っていました。** 手数で測ると「詰まって戻す」ことが罰になり、頭の中で試すより盤上で試したほうが損、という妙な圧力がかかる ―― という理屈でした。いま手数に戻したのは、**`戻す` が手数も巻き戻すから**です。無駄な手を確定させたときだけ増えるので、試すこと自体には罰がありません。そして何より、par が推定値だったころは「最短で解いた」と言えなかった ―― 時間で測っていたのは、その折衷案でもありました。**最短が確定したいま、測るべきものは手数です。**

タイムも表示していますが、星には一切関わりません。記録として見せているだけです。

星と自己ベスト（最少手数）はレベルごとに最高記録だけが残り、レベル一覧に並びます。

> 星の意味が「秒」から「手数」に変わったので、保存領域の鍵を `slidepop.v4` から `v5` に上げました。引き継ぐのは**到達レベルと設定だけ** ―― 意味の違う数字を混ぜて表示するくらいなら、記録し直してもらうほうが正直だと判断しました。

### ランキング ― 訊かずに残す。名前だけは自分で打つ

クリアすると、その記録は**必ず**そのレベルのランキングに出ます。「保存しますか？」は訊きません。

**訊いてしまうと、ランキングが実態からずれるからです。**押し忘れた回のぶんだけ記録が欠けると、「1位の人が本当に1位なのか」が誰にも分からなくなる。順位表は、載っている記録が全部そこにあって初めて意味を持ちます。

そのぶん**名前だけは自分で打ってもらいます**。クリア直後に閉じられないシートが出て、名前を決めるまで先へ進めない。**一度決めれば、次からは自動でその名前が使われます** ―― 毎回訊くのは邪魔ですし、途中で変えられると同一人物でランキングが埋まります（変えたいときは設定から変えられます）。

並べるのは**手数の少ない順**。星ではありません ―― 星は手数から決まる粗い階段でしかなく、★★★ が何人並んでも順位が付きません。同着はタイムの短い順、それも同じなら先に出した方が上。同じ名前はその人のいちばん良い1件だけを残します。

サーバは同梱していません（配信は静的ファイルだけ）。`src/config.js` の 1 行に URL を入れると世界共通に切り替わり、**空のあいだはこの端末の中だけに貯まります** ―― 名前入力もクリア時の強制保存も順位表示もそのまま動くので、接続先が無いせいで遊べなくなることはありません。投稿は必ず先に端末へ書いてから送るので、圏外でクリアしてもその回が無かったことにはなりません。

### 鍵は無い ― どのレベルにも、いつでも入れる

レベルに開放条件はありません。L1から順に上がってもいいし、いきなりL50を開いてもいい。

**理由は「詰まったプレイヤーに逃げ場が要る」から。** 本作は1問が長く（上のレベルは数十手）、読み違えると手が止まります。そこで唯一の道が「同じ問題をもう一度」しか無いと、そこでゲームが終わってしまう。どのレベルも独立した1問で、順番に意味はない ―― 別のレベルを触ってから戻ると、たいてい見えていなかった線が見えます。

保存するのは**到達レベル（まだクリアしていない、いちばん手前のレベル）**と、レベルごとの星・自己ベスト手数だけ。到達レベルは鍵ではなく、「つづきから」の行き先と、レベル一覧でいまいる場所を示すためだけに使います。

## 5. 面白さの正体

### 5-1. 二重の意味を持つ「空きマス」

空きマスは同時に二つの役割を持ちます。

1. **通路**：ブロックが通過できる空間
2. **停止位置の定義**：ブロックは「空きマスが尽きた場所」で止まる

この二面性が効きます ―― **通路を広げる操作は、同時にどこかの停止位置を壊します**。灰色を1個どかせば道は通るが、その灰色が受け止めていたブロックは、もう狙った場所で止まってくれない。

しかも空きマスは増えません（§3-③）。**限られた隙間を、通路として使うか、停止位置として使うか。** 同じ空きマスを両方の目的に使い回す順番を見つけることが、そのままパズルを解くことになります。

### 5-2. 灰色は「動く壁」

盤面のほとんどは灰色です。灰色は消えないので、**盤面の形は最後までほぼそのまま**残ります ―― 色つきを消したところで通路が広がることもありません（消えた瞬間がクリアなので）。

そして色つきは1組だけなので、**消去は最後の1手で1回だけ起きます**。手番のあいだ盤面から減るものは何もない ―― 動かせるブロックの顔ぶれは最初から最後まで変わらず、変わるのは**どこに何があるか**だけです。

### 5-3. 遠ざける ― スライドに、スライドを重ねる

本作の核。色つきの2個は、**はじめから「ぶつけられる場所」には置かれません**。ぶつけるには、片方（あるいは両方）を何手も滑らせて、ようやく隣り合わせる必要があります。

ここで効いてくるのがルール①です。**滑って止まった直後は、同じ方向へはもう進めない**（壁か他のブロックがそこにあるから止まったのだから）。したがって**ブロックの道のりは必ずどこかで曲がる**。「右へ、それから下へ、それから左へ」――この折れ線を、盤上ではなく頭の中で辿ることになります。

しかも1手滑らせるたびに、そのブロック自身が**他のブロックにとっての新しい壁**になる。灰色を1個ずらせば通れなかった道が開き、代わりに別の道が塞がる ―― **どの順で盤面を組み替えるか**という上位の問いに繋がっていきます。

初期盤面に消せる手をひとつも残さないのは、この体験を**最初の1手から**始めさせるためです。目の前に「消える手」があると、人はまずそれを押してしまう。押せる手が無ければ、読むしかない。

### 5-4. 消えるのは、最後の1手だけ

追い込みが「色つきブロック自身を動かす手」なのに対して、仕込み手は**まったく別の灰色ブロックを先に退かす手**です。上のレベルの 109 手のうち、色つきを触る手はごく一部でしかありません。

ふつうなら退屈になるところですが、本作ではここが効きます ―― 消去という中間報酬が無いぶん、**進んでいる感覚は「読みが通ったこと」からしか得られない**。だからこそ最後の1手の演出に光と音を集中させ、星は「何手で通したか」で付けています。

### 5-5. プレイヤーの思考ループ

1. **走査**：色つきの2個はどこにあるか。まっすぐ寄せられるか
2. **追跡**：どちらをどの方向へ滑らせる？ どこで止まる？
3. **迂回**：1手で届かないなら、2手なら？ 3手なら？ どこで曲がる？
4. **地形の改変**：どう滑らせても届かないなら、**どの灰色をずらせば道が変わる？**
5. **実行**：滑らせる → 盤面の形が変わる → 再走査

この「目的から逆算して通路を確保する」**再帰的な計画**が、本作の知的快感の中核です。**ぶつける場所へ行くために、その手前へ行く必要がある** ―― この再帰がブロック1個の中にも、盤面全体にも入っています。

## 6. パズル生成 ― 欲しい手数の盤面を、名指しで取り出す

「ランダムに埋めて、解けるか検証する」も、「解を作って盤面を導く」も、どちらもやめました。

**逆順構築（完成状態から1手ずつ巻き戻してブロックを置く）を捨てた理由は単純です。** それが保証できるのは「解ける手順が1本ある」ことだけで、**本当の最短手数は分かりません**。実測すると、PAR 106 手と表示していた盤面が 20 手で解けていました。看板の数字が嘘だったので、作り方ごと入れ替えています。

### いまの作り方 ― ゴールから距離を配る

```
1. 色つき2個を「くっついた状態」で置く            ← これがゴールの形（距離 0）
2. 灰色の長方形で、空きマスがちょうど3マスになるまで埋める
3. そこから指せる手を前向き BFS で展開し、到達できる配置 R を全部列挙する
4. R のうち「くっついている配置」を全部まとめて距離 0 に置き、
   逆向き BFS で 1 手戻るごとに距離 1, 2, 3 … を配る
5. 距離がちょうど N の配置を初期盤面に採る    ← N がそのレベルの最短手数
```

状態空間を丸ごと見ているので、出てくる手数は推定ではなく**厳密な最短手数**です。**これより短い解き方は存在しません** ―― 幅優先探索の性質そのものです。

同時に、**「解けない盤面」も原理的に選ばれません**（距離が付いている＝ゴールに届く）。PAR と、★★★ の基準になる最短手順は、距離が1ずつ減る手をたどるだけで手に入ります。

### 5 が肝 ― 手数を名指しで頼める

以前は「いちばん遠い配置」だけを採っていました。すると出てくる手数は運任せで、**欲しい手数を狙えません**。「候補をたくさん作って、出てきた手数の昇順に並べる」しかなく、レベル数を増やすと手数が飛び飛びになりました。

ところが 4 で作った距離マップには、**0 手から最遠まで、全部の距離が入っています**。だから「ちょうど 300 手の配置を出せ」と名指しで頼める。レベル1000本ぶんの手数カーブを埋められるのは、この一点があるからです。

### ただし、1 枚から取るのは 1 問だけ

距離マップは1枚から何十問でも切り出せます。切り出したものは灰色の位置まで違う（配置には灰色の座標も入っている）ので、一見すると別の問題です。

**それでもやりません。** ブロックの顔ぶれ ―― 2×3 が2個、3×3 が1個、1×2 が4個… ―― が同じままなので、並べて遊ぶと「さっきと同じ盤面」に見えてしまいます。実際に1枚から最大34レベルを切り出した版を作ってみたところ、**1000本中979本が使い回し**になりました。

いまは **1枚の盤面につき1レベルだけ**。1000レベルは1000枚の別々の盤面から取っています。採集の効率は4分の1以下に落ちますが（深さ363の盤面を引いても1問しか取らない）、そこは探索時間で払っています。

**「別々」の数え方は3段構えです。**

- **回転・鏡像で重なるものは同じ盤面**とみなします。裏返しただけの盤面は、人間の目には「さっきと同じ」にしか見えません。正方形の対称性8通りをぜんぶ作って、いちばん小さい表現を指紋にします（`canonicalKey`）
- **最後にくっついたときの形**も見ます。そこが同じなら、途中がどう違っても**同じパズルの別の入口**でしかない ―― 別々のプロセスが同じ配置を引き当てると、これが起きます
- **その盤面が属する連結成分**も見ます。初期盤面もゴールの形も違うのに、**滑らせていくと相手の配置に着いてしまう**ことがあります

3つめが要るのは、ひとつの成分に「くっついた形」が複数あると、上の2つをすり抜けるからです。指紋は「その成分に含まれるくっついた形すべての正準形の最小値」―― 成分のどこから始めても同じ値になるので、入口が違っても一致します。

実際、上の2つだけで焼いた1000本を調べ直すと **26本**が「滑らせて行き来できる同じ盤面」でした。しかも Lv90/91、Lv97/99、Lv104/106、Lv599/600 のように隣り合っていて、続けて遊べばすぐ気づかれる並びです。

3つを入れると、在庫から重複として弾かれるのが 4455回＋454回。焼いたあとの全件確認は `node tools/dupcheck.mjs`（4種類の重複を全レベルぶん数える。1000本で4分ほど）。

### 灰色の2マスブロックは「禁止」ではなく「少ないほうを選ぶ」

1×2・2×1 の小さい灰色が並ぶと、盤面が細切れに見えて**どこが通路なのか読みにくく**なります。減らしたい ―― のですが、測ってみると**2マスは深い盤面に構造的に必要**でした。華容道の「縦棒」と同じ役で、大きい塊の隙間を通り抜けて場所を入れ替えるのがこれの仕事です。

6×6・空き3マスで、灰色の出方だけを変えて4分ずつ測った結果：

| 灰色の出し方 | 深さ110以上 | 到達した最深 | 2マスの割合 |
|---|---|---|---|
| 全種類を等しく | 1.25 枚/分 | 131 | 67% |
| **2マスを半分に** | **3.00 枚/分** | **332** | **60%** |
| 2マスを1/4に | 0.50 枚/分 | 147 | 51% |
| 2マスを禁止 | 0 枚/分 | 90 | 0% |

**禁止すると盤面が動かなくなり、手数が伸びません。** 空き3マスぴったりに詰めることすらできず、組み立て自体が14万回失敗しました。意外だったのは、**半分に減らすほうがむしろ深くなる**こと ―― 2マスが多いと盤面がゆるくなり、ブロックの逃げ場が増えて手数が縮むようです。

採ったのは2段構えです：

1. **採集**では2マスの重みを半分にする（見た目も深さも良くなる点）
2. **焼く**ときは、同じ手数・同じ広さなら**2マスの少ない盤面から**採る

2の効き目は在庫の厚みで決まります。目標の3倍ぶん集めておくほど選べる幅が広がるので、「見た目のために深さを諦める」ことにはなりません。

### 盤面はできるだけ小さく、必要になって初めて広げる

同じ手数なら、小さい盤面のほうが読みやすく、詰まった手触りも出ます。だから **4×4 で足りるなら 4×4、そこに在庫が無ければ 5×5、6×6 …と、必要になって初めて広げます**。

広げるのは好みの問題ではなく、**その手数が小さい盤面では出せないから**です。5×5 は 81 手あたりが天井で、110 手級は 6×6 以上でしか出ません。結果として、**上のレベルだけが自然に広くなります**。

### なぜ前向き BFS も要るのか

逆向き探索を「S0 から到達できる配置 R」に閉じ込めるためです。

R は S0 から辿れる配置の全体なので、`s ∈ R` なら `s` から行ける先も R に入ります（推移性）。だから R の中だけで距離を配っても、**「R の外にもっと近いゴールがあって手数が縮む」ことは起こりません**。この性質が無いと、出した手数が最短である保証が崩れます。

### 全探索を現実的にした2つの工夫

**① 同じ形の灰色ブロックを区別しない。** 素直に実装すると、同じ形のブロックを入れ替えただけの配置が別物として数えられ、状態数が階乗で爆発します（6×6 で数十億）。形ごとに位置を並べ替えてから状態の鍵を作ると、同じ盤面は1つに畳まれ、数万まで落ちます。

**② 状態を文字列にしない。** 1 配置あたり数十本の後続を作るので、`Map<string>` にすると1配置につき数十本の文字列を確保することになり、そこが探索時間のほとんどを占めていました。専用のオープンアドレス法ハッシュ表（鍵は「各ブロックのアンカー位置を並べた `Uint8Array`」）に置き換え、探索中の確保をゼロにしています。表もキューも使い回すので、何万回回してもメモリは増えません。

### 採集は走らせながらレシピを選び直す

序盤は短い手数がいくらでも足りるのでどのレシピ（盤面の広さ・空きマス数）も当たりますが、埋まってくると**深い盤面を出せるレシピしか役に立たなくなります**。固定の重みだと後半ずっと無駄を踏むので、「1秒あたり何問採れたか」で重みを付け直す ε-greedy にしました（`tools/harvest.mjs`）。

採集は複数プロセスで並列に回せます。焼き込みは `tools/levels.mjs` が、採った在庫を手数カーブに流し込んで `src/levelData.js` を書き出します。

### 焼き込みの前に、全件を実際に指してみる

`tools/levels.mjs` は在庫を**実際に盤面へ組み直し、手順どおりに指して本当にそこで消えるか**を全件確かめます。通らないものは捨て、割合が高ければ書き出しを中止します。

これは形式的な検算ではありません。実際に、接触判定の世代印を探索ごとに消していなかったせいで「触れていない配置をゴールと読み違える」バグが入り、120 レベル中 7 件が壊れたデータになりました ―― この関門で止まりました。

### 初期盤面からは何も消せない

採るのは**距離 2 以上**の配置だけなので、初期盤面でどのブロックをどう動かしても何も消えません（1手で届くなら距離 1 です）。色つきは1組しかないので、**消えるのはいちばん最後の1手だけ** ―― 300手のレベルなら 299手ぶん滑らせ続けて、やっと消えます。

目の前に「消える手」があると、人はまずそれを押してしまう。押せる手が無ければ、読むしかない。**この体験を最初の1手から始めさせるための設計です。**

### データの詰め方

素直に JSON で書くと 300 手の問題は1本 6〜7KB ―― 1000 本で 3MB になり、アプリ本体の 15 倍という馬鹿げた大きさになります。そこで **1 レベル = 1 本の文字列**に潰しました（`src/levelCodec.js`）。潰せるのは盤面に出てくるものが少ないからです：

- ブロックは全部長方形で、幅も高さも 1〜3 マス ―― 形は 9 通り＝**1 文字**
- 盤面は 8×8 まで ―― 位置は 0〜63 で **1 文字**
- 色つきは必ず2個で必ず先頭 ―― **色を書く必要が無い**（3個目からは全部灰色）
- 1手は「どのブロックを・どの向きへ・何マス」―― 向き4×距離7で **2 文字**

## 7. 操作とフィードバック

### 操作体系

- **スワイプ**：ブロック上で上下左右にドラッグ。26pxの閾値を超えた瞬間に発動
- **着地予測ゴースト**：ドラッグ中、最終停止位置に半透明のゴーストと矢印を表示。「どこで止まるか」を可視化し、読みを助ける
- **クリック選択＋矢印キー**：精密操作・キーボード派向け
- **無効手**：動かせない方向へスワイプすると、ブロックが小刻みに揺れて拒否（手数に数えない）

### フィードバック設計 ― 文字は出さない

以前は「○個消し！」「◯コンボ」という浮き文字を出していました。**廃止しています。** 盤面の上に文字を置くと、いちばん見たいもの（次の一手）が隠れるうえ、読む時間だけテンポが落ちる。祝うのは**光と音**だけにして、連鎖の深さは音程・光の強さ・揺れの大きさが伝えます。

| 行為 | 反応 |
|---|---|
| スライド | easeOutCubicの加速→減速、残像トレイル、着地の小刻みな沈み込み |
| 消去 | マスが光に開く → 破片が散る → ネオンの輪が広がる → 一瞬白む → 画面が揺れる |
| 連鎖 | 音程が階段を上がり、光と揺れが 1 段ずつ強くなる（頭打ちあり。眩しすぎると読めない） |
| 3個以上まとめて消える | 直前に 0.1 秒だけ止める（タメ）。止めてから解放すると同じ演出でも強く感じる |
| 選択中 | 白く脈動するアウトライン |
| クリア | 星が1つずつ跳ねて出る |

### サウンド ― 重い塊を押す音を、いちばん作り込む

このゲームでプレイヤーが**いちばん多く聴く音は「ブロックを動かした音」**です。1問で 300 手指すなら 300 回鳴る。ここが軽いと、盤面が紙のように感じられて「壁を押しのけている」という実感そのものが消えます。だから移動音だけは独立した設計にしてあります。

移動は **3 段階**で鳴ります。着地の一撃だけでは重さは出ません ―― 動き出しの抵抗と、動いているあいだ鳴りっぱなしの摩擦があって、はじめてぶつかった音に意味が出ます。

- **押し出しの抵抗**：低く短い一撃。石を押し始めた瞬間の "グッ"
- **引きずる摩擦**：ノイズをループさせ、ローパスの角を「開いて閉じる」ように動かす。開くところが加速、閉じるところが減速に聴こえるので、目に見えている滑走とひとつながりになります。**滑走アニメとまったく同じ長さ**だけ鳴らす（音が先に終わると軽くなる）。帯域は 600Hz 以下 ―― 上が出ると砂や紙になり、石や木の塊には聴こえません
- **着地の衝撃**：5 層を重ねます。① 100Hz 台から 40Hz 台へ**落ちる**正弦波 ② 塊の胴鳴り ③ 低く絞った接触ノイズ ④ ごく短い中高域の一撃 ⑤ 受け止めた板の余韻

①の「落とす」が重さの芯です。同じ低さでも、一定の周波数を鳴らすとただの "ブーッ" にしかならない。上から下へ落として初めて**質量のあるものが着いた**ように聴こえます（実際の衝突音でも、材料がたわんで戻るあいだに基音が下がる）。④は逆で、低音だけだと**重いのではなく「こもった」音**になってしまう。輪郭を出すために一瞬だけ中高域を混ぜます。

距離が長いほど低く・長く・強くなります。10 マス滑らせた 1 手が、1 マスの 1 手と同じ音で終わらないように。

残りの音色は 3 つ。

- **ウッドクリック**：掴む合図と UI ボタン。帯域を絞ったノイズの一撃（木を叩いた芯）＋ 上から落ちてくる基音（詰まった鳴り）＋ 4 倍音を少しだけ（マリンバの丸み）
- **グラスシャター**：消えた瞬間だけ。非整数倍（`1, 2.41, 3.86, 5.62, 7.71, 9.94`）の部分音を少しずつ遅らせて散らす。整数倍だと「鐘」に、非整数倍だと「ガラス」に聴こえる
- **低いほめ音**：解に近づく手を指したときの相づち。F3 に完全五度を重ねただけの、低くて丸い和音。**祝う音ではありません** ―― 祝ってしまうとクリアの音が軽くなるので、消去音よりずっと下の音域に置いて重ならせない

連鎖するとウッドクリックの音程がペンタトニックの階段を上がっていきます。**「次はもっと高い音を聴きたい」**という欲求が、そのまま次の一手を探す動機になります。ハプティクスは音を出す関数の中で一緒に鳴らすので、指と耳がずれません。着地の触覚は音と同じ形（短い前触れ → 間 → 長く重い本体）にしてあります。

### 進み具合は、色の温度で伝える

**遊んでいる最中、いまの局面から解までの残り手数を厳密に知っています。**

レベルを読み込むとき、その盤面で到達できる配置を全部展開して、すべての配置についてゴールまでの最短距離を配ります（`src/exact.js` の `Explorer`。もともとレベルを焼くのに使っていた全探索を、そのまま実行時にも回している）。以後はどの局面でも表を1回引くだけで残り手数が出ます。

**そのために遊びを止めることはしません。** 一気に回すと、深い盤面では0.5秒以上のあいだ画面が固まります。遊び始める前にそれだけ待たせるのは筋が悪いので、**フレームの余りだけを使って少しずつ**配ります（7ms、アニメーション中は2ms ―― いちばん見られている0.3秒は譲る）。レベルを開いた瞬間からふつうに指せて、時計も動く。

配り終わるまでのあいだは、焼いてある手順と色つき2個の隙間で色をおおまかに動かし、表ができた時点で厳密な値へ切り替わります。表示用の進行度がなめらかに追いつくので、切り替わりは段としては見えません。**待たせない代わりに、最初の数秒だけ色が少し雑になる** ―― という交換です。

色はそれで動きます。**最短40手の盤面なら、色は40段。** 残り手数が1減れば色が1段進み、1増えれば1段戻る。

焼いてある解答と突き合わせるやり方では、こうはできません。**最短の道は1本ではない**ので、別の最短手順に乗り換えただけの手を「間違い」と誤解してしまいます。距離を全部の配置に配ってあれば、プレイヤーがどこへ迷い込んでも、そこからの残り手数がそのまま引ける。

色の道すじは 冷たい藍 → 青 → 青緑 → 緑 → 琥珀 → 朱。動くのは**色つきブロックと背景**だけです。1手ぶんの変化は0.5秒ほどかけて渡すので、点滅ではなく景色として動きます。

**「あと◯手」とは絶対に出しません。**数字を出すと、盤面ではなく数字を見ながら遊ぶことになる。温度だけが変わるなら、視線を盤面から外さずに近さが伝わります。

背景には**色つきブロックとまったく同じ色**を、うんと薄めて敷いています（背景だけ違う色にすると、2つの色が画面で喧嘩する）。濃さは上下で変えません ―― 変えると、色が違うのか濃さが違うのかが読めなくなります。

**色が変わるときだけ、下から満ちます。** ブロックの色は1手ぶんまるごと切り替わりますが、画面いっぱいの背景まで同時に切り替わると、視界の端で照明が点滅したように見えました。そこで前の色を上に残したまま、新しい色を下端から押し上げます（約1.1秒）。境目は画面の高さの±26%ぶんぼかしてあるので、横線が横切るのではなく水位が上がるように見えます。レベルを跨いだときだけは満ちきった状態から始めます ―― 前のレベルの色が上に残っていると、新しい盤面の色が何を指しているのか読めません。

同じ物差しで 👍 のスタンプも出ます。**残り手数が減った手には 75%**、減ってはいないが色つき2個がこれまででいちばん近づいた手には 33%。文字を出さないという原則の唯一の例外ですが、読む必要のない形（絵文字）にしてあるので、目を上げずに済みます。

> 全探索が使えない盤面（状態数が上限を超えるなど）では、焼いてある手順の線上にいるかと、色つき2個の隙間がどれだけ詰まったかで測ります。色の動きは粗くなりますが、遊べなくはなりません。

### 見た目 ― デザインは 2 つ

設定シートからいつでも切り替えられ、見た目だけが変わります（盤面もルールも一切変わりません）。

- **クリスタル**（既定）―― 実機で撮ったガラスのブロックの**写真**を、そのまま切り出して貼ったもの
- **プレーン** ―― 厚みも面取りも影も持たない、色そのものの平らな面。目が拾うものが「色と形」しか無いので、どのブロックがどこまでかが一瞬で読めます

既定をクリスタルにしてあるのは、**初めて開いた人が最初に見る画面**だからです。読みやすさだけならプレーンが勝ちますが、それは「速く読む」ための道具で、初めての画面が伝えるべきものではありません。読みやすさが要るときは設定でいつでも戻せます。

#### 素材を 6 つ廃止しました

昔はここに、手続きで描いた素材（石・木・金属・紙・布・描いたガラス）が並んでいました。ノイズから「高さの場」を作り、その傾きから陰影を計算する（バンプマッピング）やり方で、拡大すれば見事に見えます。

ただ、**1 マスが 40px そこそこになると、模様がブロックの輪郭と同じ細かさになり、形が模様に埋もれて読めなくなります**。盤面を読むゲームでそれは致命的なので、どれも「地の上に薄く敷く」ところへ落ち着きました ―― そして薄く敷いた石と薄く敷いた紙は、遊んでいるあいだ見分けが付きません。名前だけが違う 6 つを並べておく意味がありませんでした。

残したのは**役割がはっきり違う 2 つ**だけです。廃止した名前を設定に持ったままの端末は、黙ってプレーンへ落ちます（設定が古いだけで、遊べなくはなりません）。

#### クリスタルは、描かずに貼る

ガラスは「表面の凹凸」ではなく**中を通ってきた光**でできています。面取りの向こう側が透けて重なり、角では全反射して白く跳ね返る ―― 高さの場は表面しか作れないので、どれだけ手を入れても「ガラスに似せた石」より先へ行けませんでした。

そこでクリスタルは、実機のスクリーンショットからブロックを 1 個ずつ切り出して、そのまま貼っています。

- 写真は 4 枚だけ（1×1・2×1・1×2・2×2）。**1 マス 160px の無色（グレースケール）**
- 貼るときは **9 分割** ―― 角と辺は伸ばさず、中央だけを伸ばします。エメラルドカットの面取りは「一定の幅の帯」なので、1×1 でも 3×3 でも写真と同じ太さのまま収まります。**4 枚で全部のレベルに効く**のはこのためです
- **色は貼ってから被せます**（進行度の色相を `'color'` で重ねる）。明るさは写真のまま残るので、ガラスの陰影を保ったまま、色だけが手数に合わせて動きます ―― 進行度が色の目盛りである、というこのゲームの仕組みは写真の上でもそのまま働きます

#### 灰色と色つきの見分けは、色相ではなく明暗で

色つきブロックの色は進行度で動きます（藍 → 青 → 緑 → 琥珀 → 朱）。ここで色相だけに頼ると、**進行度が灰色の近くを通ったときに 2 個を見失います**。

そこで灰色ブロックと色つきブロックで**明るさそのものを離して**あります。クリスタルなら、無色のガラスと染めたガラス。色相はその上に乗ります。

色相を寄せるときも、明るさは**目に見える明るさ（luma）で揃え**ます。HSL の L は色相を見ていないので、同じ L でも黄色は白に近く青は闇に近い ―― L だけ揃えると、琥珀を通るときにだけ色つきが明るくなって灰色と紛れます。

#### 盤面という面は無い

**ブロックは背景の上に直接載っています。** 受け皿も枠も空きマスの窪みも描きません ―― キャンバスを透かして、盤面のあたりも背景（`.game-aura`）とまったく同じ色にしてあります。

昔はここに「盤面」を敷いていました。枠を立て、床を落とし、空きマスを一段深い窪みにして、ブロックが箱に収まっているように見せる ―― けれど**その面は、遊ぶのに何ひとつ足していませんでした**。どこがマスかはブロックの並びで分かりますし、通路は「ブロックが載っていないところ」として読めます。面が 1 枚あるぶん、背景・受け皿・ブロックと明るさの段が 3 つになり、いちばん強い境目がブロックの輪郭でなくなっていました。

写真のクリスタルにとっては、なおさら邪魔でした。ガラスは後ろに何があるかで見え方が決まるので、白い台を挟むと台の白しか透かせません。台を外すと、背後の背景がそのままガラスを通って見えます。

いま画面にある明るさの段は「背景」と「ブロック」の 2 つだけです。

### Liquid Glass ― 浮いている面だけがガラス

盤面はフラット、その上に浮く UI（ツールバー・シート・ボタン・チップ）だけが Z 軸の階層を作ります。ガラスの処方は全面で共通です。

- 背景を大きくぼかし、彩度を上げる（`blur(34px) saturate(200%)`）。後ろの色を吸って、ガラス自体がうっすら色づく
- 縁は 2 本 ―― 上端に白い光の線、全周に極薄の暗いヘアライン。白の上でも黒の上でも輪郭が消えない
- 上面の照り返しは要素の `background` に敷く。オーバーレイを重ねないので、文字の上に膜が乗らない

ホーム画面にだけ、ブロックの4色をごく淡く広げた光を敷いてあります。**ガラスは「後ろに何かある」ときにしか美しくならない**ためで、その上にガラスのボタンを置くと、背景の色を拾って縁が色づきます。

## 8. 難易度を構成する要素

難易度の指標は**ひとつだけ**です ―― **厳密な最短手数（PAR）**。推定値でも代理指標でもないので、レベル順に並べるだけで難易度順になります。

そのうえで、同じ手数の中身を分けているのが次の要素です。

- **追い込みの深さ**：1組を消すまでに重ねるスライドの数。色つきは1組しかないので、**PAR − 1 手すべてが追い込み手**。1手先ではなく n 手先の盤面を頭の中で作る必要がある
- **空きマスの少なさ**：空きが3マスしか無い盤面では、そもそも滑れる距離が短い。ブロック1個を動かすだけでも「どこを空ければ通れるか」から考えることになる
- **ブロックの大きさ**：3×3 のブロックは幅3の通路しか通れない。大きいほど道が減り、同じ盤面でも道のりが長くなる
- **滑走距離**：長いスライドは長い通路を要求する
- **仕込み手**：**探すべきものが「消える手」でも「消したいブロック」でもない**。盤面のどこを触ればよいのか自体が問題になる
- **盤面の広さ**：4×4 から 8×8 まで。**難易度ではなく見た目の変化**として振っている（広いほど手数が伸びるわけではない ―― むしろ縮む）

かつては色数・埋め率・追い込みの目標手数・仕込み手の本数…と生成器のパラメータを並べていましたが、**どれも「たぶん難しくなるはず」の代理指標**でした。全探索で本当の最短手数が出るようになったので、代理指標は全部やめています。

「読みの深さ」を測る指標として、`npm run verify` は **最長の無消去連続**（最短手順の中で何も消えない手が最大何手続くか）を出します。色つきは1組しかないので、これは常に **PAR − 1** ―― レベル1000 なら **299 回スライドを重ねて、やっと1組**。

## 9. 位置づけと独自性

| ゲーム | 移動 | 消去 | 重力 |
|---|---|---|---|
| テトリス | 落下・回転 | ライン揃え | あり |
| ぷよぷよ | 落下 | 同色4連結 | あり（連鎖） |
| SameGame | クリック | 同色連結 | あり |
| Rush Hour | スライド | なし | なし |
| アイススライド系 | 決定論的スライド | なし | なし |
| **SLIDE POP!** | **決定論的スライド** | **同色ペア接触** | **なし** |

本作は**「アイススライドの決定論性」×「接触消去」×「重力なし（空間が資源）」**という、それぞれ実績のある mechanic の未踏の交差点に位置しています。特に「消去が通路を生み、通路が消去を可能にする」という**循環構造**は、重力型パズルにも純スライドパズルにも存在しない、本作固有のものです。

そのうえで本作は、**消去そのものを遠ざけました**。色つきの2個は1手ではぶつからず、ぶつけに行く道のりを何十手も組み立てる必要がある。盤面の大半を占める灰色は消えないので、**通路は自分で並べ替えて作る**しかありません。結果として、アイススライド系の「1本の折れ線を読む」楽しさと、接触消去系の「盤面のトポロジーが書き換わる」楽しさが、1つの手番の中で重なります。

## 10. 拡張の方向性

- **デイリーパズル**：その日のレベルを全プレイヤー共通に・タイムのランキング
- **リプレイ共有**：解の手順をシリアル化して共有・検証可能に
- **最短手順の可視化**：詰まったとき、次の1手ではなく折れ線そのものを見せるモード（初級者向けの補助輪）
- **実装済み**：ステージ制（レベル1から上限なし。最短手数が Lv1 の 2 手から Lv1000 の 300 手まで伸びる）、焼き込みデータによる全端末共通の譜面、**鍵の無いレベル選択**、**手数による星評価と自己ベスト**

---

**総括**：SLIDE POP!は「空きマスという負の空間を、消去によって稼ぎ、滑走によって消費する」ゲームです。ルールは3つしかないのに、盤面のトポロジーが手ごとに書き換わることで、深い再帰的計画が生まれます。

そして**同色ペアは、はじめから隣り合ってはくれない**。初手からすでに、目の前に押せる手はありません。スライドにスライドを重ねて、ぶつける場所まで運ぶ道筋を、頭の中で組み立てるしかない。星が手数で決まるのは、基準の par が**厳密な最短手数**だからです ―― ★★★ は「最短で解いた」という、あいまいさのない達成になります。

生成アルゴリズムは「解けること」だけでなく **「表示している手数が本当に最短であること」** まで構造的に保証します。プレイヤーは常に「自分が悪かった」と納得できる――純粋パズルとして最も大切な信頼関係を、設計の土台から持っているゲームです。
