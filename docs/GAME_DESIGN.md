# SLIDE POP! ― ゲームデザインドキュメント

## 1. コンセプト

**「滑らせて、同色をぶつける」**

ブロックは押せば壁にぶつかるまで一直線に滑る。同じ色のブロック同士が触れれば弾けて消える。重力も連鎖もない。**盤面にある色つきのブロックは1組（2個）だけで、その2個をぶつけたらクリア**です。

やることはそれだけなのに、簡単ではありません。**盤面のほとんどは灰色のブロック**で、灰色は何と触れても消えないからです。色つきの2個は灰色に阻まれて、まっすぐには近づけない。**灰色を押しのけて道を作り、そこを通して運ぶ** ―― それがこのゲームの中身です。

灰色も押せば同じように滑ります。つまり壁でありながら、**自分で並べ替えられる壁**。1個ずらせば通路が開き、同時にどこか別の通路が塞がる。

だから遊びの中身はこうなる ―― **「ここへ滑らせると、次にどこへ滑れるようになるか」を、ぶつけられる場所にたどり着くまで頭の中で辿る。** 目の前に「消える手」が無いからこそ、読むしかない。いちばん上のレベルでは、**84手ぶんそれを積み上げます**。

そして表示している手数は**厳密な最短手数**です。「解ける手順が1本ある」ではなく、**それより短い解き方は存在しない**ことまで確かめてあります。

## 2. ゲーム概要

| 項目 | 内容 |
|---|---|
| ジャンル | 空間パズル（スライド×接触消去） |
| 盤面 | 5×5 / 6×6 / 7×7 |
| ブロック | 大小の長方形。**色つきは 1×2 固定**、灰色は 2×2・3×2・2×3・3×1・1×3 |
| 色つき | **1組（2個）だけ**。この2個をぶつけたらクリア |
| 灰色 | **どの色とも消えない**。押せば同じように滑る「動く壁」 |
| 初期配置 | 埋め率 68% 〜 92%。ほとんどのマスがブロックで埋まっている |
| 初期条件 | 色つきの2個は隣接していない／**初手に消せる手がひとつも無い**／必ず解ける |
| 1プレイ | 2〜84手。**表示している手数は厳密な最短手数**で、これより短い解き方は存在しない |
| 進行 | 60レベルを事前生成して同梱。61以降は先頭に戻る。**鍵は無く、どのレベルにもいつでも入れる** |
| 評価 | **解決時間**による星3段階（目安以内／その2倍以内／クリア） |
| 情報 | 完全情報・初期配置以降ランダムなし |

### レベル進行

難易度の物差しは**厳密な最短手数そのもの**です。候補をたくさん作ってから最短手数の昇順に並べ、その順番がそのままレベル順になります。

| 変わるもの | 進み方 |
|---|---|
| 最短手数 | L1で**2手** → いちばん上で**84手**。同じ手数は3レベルまで |
| 盤面 | 5×5 / 6×6 / 7×7。**広いほど難しいわけではない** |
| 埋め率 | 68% 〜 92% |
| 灰色の数 | 3〜12個。数と形が「通路の迷路」を決める |

L1〜L12 は 2〜5手の練習問題で、操作を掴むためのものです。そこを抜けると1組を消すまでに5手以上を重ねることになります。

**盤面が広いほど難しい、ではありません。** いちばん難しいレベルは 6×6 です ―― 広い盤面はブロックが遠回りできてしまうぶん、かえって最短手数が縮む。**詰まった小さい盤面**のほうが、灰色の間を縫う道のりが長くなります。

### なぜ色つきは1組だけなのか

はじめは多色でした。**色を増やしても最短手数が伸びないと分かって、1組に絞りました。**

同色ペアが n 組あると、最短解は「n 組のうち**いちばん近い1組**」で決まってしまいます。組が増えるほど「たまたま近い組」が現れやすくなるので、**組を足すことは最短手数を縮める方向にしか働きません**。実測でも `色数 × 1.8手` からどうやっても動かず、灰色を混ぜても、形を変えても、埋め率を上げても同じでした。

伸ばすには逆に、**色を1組まで減らして、その1組をできるだけ遠ざける**しかない。そのための仕掛けが §6 の厳密生成です。

### 埋め率を上げる意味

埋め率は高いほうが難しく、そして**探索も速くなります**。ブロックがぎっしり詰まっていれば動かせる方向自体が減るので、到達できる盤面の数が落ちて全探索が現実的になる ―― 難易度と生成コストが同じ方向を向いている、珍しい設計です。

ただし上限はあります。詰めすぎるとブロックがほとんど動けなくなり、**最短手数はかえって落ちます**（8×8 を 91% まで詰めたら4手になりました）。68〜92% がその手前の帯です。

### 用語の定義

- **ブロック（ピース）**：長方形の剛体。移動・消去の最小単位
- **色つき**：消える2個。1×2 の長方形が1組だけ置かれる
- **灰色（ブロッカー）**：何と触れても消えないブロック。押せば滑るので、盤面の形を変える「動く壁」として働く
- **最短手数**：その盤面をクリアするのに必要な手数の下限。**推定ではなく、全状態を展開して求めた厳密な値**
- **セル（マス）**：盤面の1区画
- **スライド**：ブロックが上下左右のいずれかに、障害物にぶつかるまで一直線に移動すること
- **接触**：異なるブロックのセルが上下左右で隣り合うこと（斜めは含まない）
- **通路**：ブロックが通過できる空きマス

## 3. ルールの三本柱

### ① スライド ― 「距離は選べない」

プレイヤーができる操作は**「どのブロックを、どの方向に押すか」**の二択だけです。押されたブロックは、壁か他のブロックにぶつかるまで滑り続けます。1マスで止めることも、手前で止めることもできません。

この**「距離の制御不能性」**が設計の要です。

- 全ての手が**決定的**になる。運も隠し情報もない
- 「押す前に、どこで止まるかを読む」ことがそのままゲームになる
- 1手1手の結果が盤面全体に波及するため、読みが深い

スライドはブロック単位（剛体）で行われます。I字型が縦に滑るとき、4セルすべてが同時に移動し、いずれか1セルでも障害物に触れれば全体が止まります。自分の元いたセルは通過可能です（自分が退いた後なので）。

### ② 同色接触消去 ― 「触れた瞬間、消える」

ブロックが滑り終えた直後、盤面が走査されます。上下左右で同じ色のブロックが触れ合っていれば、**その2個が即座に消去**されます。列を揃える必要はありません。色が触れれば、それで終わりです。

重要な細則として、**消去の単位は「ブロック」であり、単体のブロックは自己消去しません**。1×2 のブロックは2セルとも同色ですが、それは「1つの塊」として扱われます。消去が起きるのは、**2つのブロックが接触したとき**だけです（セル単位なら初期盤面が瞬時に全滅します）。

そして**灰色は、この判定から外れています**。灰色同士が何個くっついても、色つきと接しても、何も起きません。盤面の大半を占めるブロックが「消えない」ことが、次の③の意味を変えています。

### ③ 重力なし ― 「空きマスは、増えない」

消去されても、他のブロックは落下しません。すべてがその場にとどまります。

以前の多色版では、ここは「消すたびに通路が生まれ、盤面が徐々に解けていく」という設計でした。**いまは違います。** 消えるのは色つき1組だけで、しかもそれが消えた瞬間がクリアなので、**プレイ中に空きマスが増えることは一度もありません**。

つまり盤面は**最初から最後まで、同じ数の空きマスしか持たない**。68〜92%が埋まった盤面で、残ったわずかな隙間だけを使って、色つきを運びきることになります。

- 消去は最後の1手にしか起きない（自動連鎖ゼロ）
- 空きマスは増えも減りもしない。**与えられた隙間が、最初から最後まで唯一の資源**
- 盤面の形を変えられる唯一の手段は、**ブロック自体を並べ替えること**

「消して道を開ける」ができない以上、道は**押しのけて作る**しかない。ここが本作固有の手触りです。

## 4. 勝敗条件と評価

- **勝利**：色つきの2個をぶつける（灰色は最後まで盤面に残ります）
- **敗北条件は無い**

初期の設計には「どう動かしても同色接触を作れない＝デッドロック」という敗北条件がありました。これは**廃止しています**。いまの設計では、**消せる手が無いのが通常の局面**です ―― 84手のレベルなら、83手ぶんは消せる手がありません。「いま消せない」ことは詰みではなく、**通路を作るところから始めろという合図**。敗北を宣言する代わりに、`戻す`と`やり直す`をいつでも使えるようにしています。

### 星 ― 解決時間で決まる

| 星 | 条件 |
|---|---|
| ★★★ | **目安の時間以内** |
| ★★ | その**2倍**まで |
| ★ | クリア |

目安は `20 + 最短手数×9 + 色数×4` 秒。L1で0:42、いちばん上のレベルで13:00前後です。ゲーム画面のタイムは★★★を過ぎると黄、★★も過ぎると赤に変わり、**いま星いくつぶんの位置にいるか**が常に分かります。

**なぜ手数ではなく時間なのか。** 手数で測ると「詰まって戻す」ことが罰になります。すると**頭の中で試すより盤上で試したほうが損**という妙な圧力がかかり、`戻す`が使いにくくなる ―― 本来いちばんフェアな道具なのに。このゲームで時間がかかるのは指が遅いからではなく、盤面を読んでいるからです。時間で測れば `戻す` も `やり直す` も自由に使えて、それでも「読み切ってから指した人」がいちばん速い。**測りたいものを、そのまま測る。**

時計はゲーム画面を見ている間だけ進みます ―― ルールや設定のシートを開くと止まり、タブを離れても止まる。**ヒントは1回 +20秒**：星を丸ごと奪うのではなく、少しだけ重くする。詰まった人が先へ進めることのほうが大事なので、禁止も減点もしません。`やり直す`を押すと時計も0に戻り、**同じ盤面を「読み切ってから指す」挑戦**として遊び直せます。

星と自己ベストタイムはレベルごとに最高記録だけが残り、レベル一覧に並びます。

### 鍵は無い ― どのレベルにも、いつでも入れる

レベルに開放条件はありません。L1から順に上がってもいいし、いきなりL50を開いてもいい。

**理由は「詰まったプレイヤーに逃げ場が要る」から。** 本作は1問が長く（上のレベルは数十手）、読み違えると手が止まります。そこで唯一の道が「同じ問題をもう一度」しか無いと、そこでゲームが終わってしまう。どのレベルも独立した1問で、順番に意味はない ―― 別のレベルを触ってから戻ると、たいてい見えていなかった線が見えます。

保存するのは**到達レベル（まだクリアしていない、いちばん手前のレベル）**と、レベルごとの星・自己ベストタイムだけ。到達レベルは鍵ではなく、「つづきから」の行き先と、レベル一覧でいまいる場所を示すためだけに使います。

## 5. 面白さの正体

### 5-1. 二重の意味を持つ「空きマス」

空きマスは同時に二つの役割を持ちます。

1. **通路**：ブロックが通過できる空間
2. **停止位置の定義**：ブロックは「空きマスが尽きた場所」で止まる

この二面性が効きます ―― **通路を広げる操作は、同時にどこかの停止位置を壊します**。灰色を1個どかせば道は通るが、その灰色が受け止めていたブロックは、もう狙った場所で止まってくれない。

しかも空きマスは増えません（§3-③）。**限られた隙間を、通路として使うか、停止位置として使うか。** 同じ空きマスを両方の目的に使い回す順番を見つけることが、そのままパズルを解くことになります。

### 5-2. 灰色は「動く壁」

盤面のほとんどは灰色です。灰色は消えないので、**盤面の形は最後までほぼそのまま**残ります ―― 色つきを消したところで通路が広がることもありません（消えた瞬間がクリアなので）。

だからといって置き物ではありません。**灰色も押せば滑る。** 動かせば通路が開き、同時にどこか別の通路が塞がる。「色つきをどう運ぶか」だけでなく、**その道を作るために灰色をどう並べ替えるか**が問題になります。壁でありながら、自分で並べ替えられる壁 ―― ここが Rush Hour 的な手触りを生んでいます。

### 5-3. 遠ざける ― スライドに、スライドを重ねる

本作の核。色つきの2個は、**はじめから「ぶつけられる場所」には置かれません**。ぶつけるには、片方（あるいは両方）を何手も滑らせて、ようやく隣り合わせる必要があります。

ここで効いてくるのがルール①です。**滑って止まった直後は、同じ方向へはもう進めない**（壁か他のブロックがそこにあるから止まったのだから）。したがって**ブロックの道のりは必ずどこかで曲がる**。「右へ、それから下へ、それから左へ」――この折れ線を、盤上ではなく頭の中で辿ることになります。

しかも1手滑らせるたびに、そのブロック自身が**他のブロックにとっての新しい壁**になる。灰色を1個ずらしただけで、さっき読んだ折れ線が丸ごと使えなくなることもあります。

初期盤面に消せる手をひとつも残さないのは、この体験を**最初の1手から**始めさせるためです。目の前に「消える手」があると、人はまずそれを押してしまう。押せる手が無ければ、読むしかない。

### 5-4. 消えるのは、最後の1手だけ

色つきが1組しかないということは、**手順の最後の1手まで、盤面から何も減らない**ということです。84手のレベルなら、**83手ぶん何も起きません**。

ふつうなら退屈になるところですが、本作ではここが効きます ―― 消去という中間報酬が無いぶん、**進んでいる感覚は「読みが通ったこと」からしか得られない**。だから star を手数ではなく時間で付けているし、消える瞬間の演出に光と音を集中させています。

### 5-5. プレイヤーの思考ループ

1. **走査**：色つきの2個はどこにあるか。まっすぐ寄せられるか
2. **追跡**：どちらをどの方向へ滑らせる？ どこで止まる？
3. **迂回**：1手で届かないなら、2手なら？ 3手なら？ どこで曲がる？
4. **地形の改変**：どう滑らせても届かないなら、**どの灰色をずらせば道が変わる？**
5. **実行**：滑らせる → 盤面の形が変わる → 再走査

この「目的から逆算して通路を確保する」**再帰的な計画**が、本作の知的快感の中核です。**ぶつける場所へ行くために、その手前へ行く必要がある** ―― この再帰がブロック1個の中にも、盤面全体にも入っています。

## 6. パズル生成 ― ゴールからいちばん遠い盤面を選ぶ

### 一度失敗している

最初は**「解の逆順構築」**でした。完成状態から手順を1手ずつ逆再生してブロックを置いていく方式で、「解ける手順が1本ある」ことは構造的に保証できます。

**保証できるのはそこまででした。** 作った手順が最短だとは限らない ―― 実際には**ずっと短く解けてしまい**、PAR 106手と表示していた盤面が20手で終わることさえありました。プレイヤーに見せていた数字が嘘だったわけです。

原因は「混ぜ方」にあります。ゴール状態から適当に手を戻していく操作は**ランダムウォーク**なので、手数をいくら重ねてもゴールの近所をうろうろするだけで、遠くへは行きません。**手順の長さと、盤面の難しさは別物でした。**

### いまの方式 ― 全部展開して、いちばん遠い配置を採る

そこで発想を変えました。手順を作るのをやめ、**その盤面で到達できる配置を全部展開します**（`src/exact.js`）。

1. 色つきの 1×2 ペアを**くっついた状態**（＝ゴール）で置く
2. 灰色の長方形で、狙った埋め率まで盤面を埋める
3. そこから指せる手を**幅優先で展開し、到達できる配置をすべて列挙する**
4. 「くっついている配置」全部を始点に**逆向きの幅優先探索**を回し、全配置について**ゴールまでの最短距離**を求める
5. **いちばん遠い配置**を初期盤面に採る。そこまでの距離が、そのレベルの最短手数

状態空間を丸ごと見ているので、出てくる手数は推定ではなく**厳密な最短手数**です。**これより短い解き方は存在しません** ―― グラフ上の最短距離そのものなので、証明が要りません。

副産物として、**その距離を実現する手順**（＝最短手順）もそのまま手に入ります。

### 同じ形の灰色は区別しない

ここが実装上の山でした。素直に書くと、**同じ形の灰色を入れ替えただけの配置が別物として数えられ**、状態数が階乗で爆発します（6×6 で数十億に達し、どの設定も探索が終わりませんでした）。

形ごとに位置を並べ替えてから状態の鍵を作ると、同じ盤面は1つに畳まれ、**数千まで落ちます**。この一点で全探索が現実的になりました。

### 事前生成して焼き込む

1問あたり数秒〜数十秒かかるので、実行時には作りません。`node tools/levels.mjs [レベル数]` で**あらかじめ生成して** `src/levelData.js` に焼き込み、ゲーム側はそれを読むだけです（読み込みは30〜130ms）。

レベル順は「作ってから最短手数の昇順に並べ替えた」ものです。盤面サイズや埋め率をいくら振っても**出てくる手数は前もって読めない**ので、狙って作るのではなく、作ってから並べています。同じ手数は3レベルまでに制限しました ―― 出やすい手数ばかりが並ぶと「上がった感じ」が消えるためです。

### ヒントは、最短手順の上でだけ

記録してあるのは最短手順**1本**です。現在の局面を指紋で照合し、手順の途中なら次の1手を示します。

外れていたら答えようがありません ―― 別の道をその場で探索し直すには重すぎる（84手級の盤面は、事前に全状態を展開して初めて出せた数字です）。そこで**外れたときは「最初からやり直しますか？」と訊きます**。適当な手でお茶を濁すより、出せないことをはっきり伝えるほうが誠実だからです。やり直せば第1手からまた出せるし、「このまま続ける」を選べばそのまま自力で進められる。**訊かれただけでは時間を足しません** ―― 何も教わっていないのに罰を受けるのは筋が通らないので。

> 判定は「記録してある1本」との照合なので、**同手数の別ルートで解いている場合も「外れている」と判定されます**。文言を「記録してある最短手順」としてあるのはそのためです。全配置の距離マップごと焼き込めば別解も許せますが、いまはやっていません。

## 7. 操作とフィードバック

### 操作体系

- **スワイプ**：ブロック上で上下左右にドラッグ。26pxの閾値を超えた瞬間に発動
- **着地予測ゴースト**：ドラッグ中、最終停止位置に半透明のゴーストと矢印を表示。「どこで止まるか」を可視化し、読みを助ける
- **クリック選択＋矢印キー**：精密操作・キーボード派向け
- **無効手**：動かせない方向へスワイプすると、ブロックが小刻みに揺れて拒否（手数に数えない）

### フィードバック設計 ― 文字は出さない

以前は「○個消し！」「◯コンボ」という浮き文字を出していました。**廃止しています。** 盤面の上に文字を置くと、いちばん見たいもの（次の一手）が隠れるうえ、読む時間だけテンポが落ちる。祝うのは**光と音**だけにして、連鎖の深さは音程・光の強さ・揺れの大きさが伝えます。

| 行為 | 反応 |
|---|---|
| スライド | easeOutCubicの加速→減速、残像トレイル、着地の小刻みな沈み込み |
| 消去 | マスが光に開く → 破片が散る → ネオンの輪が広がる → 一瞬白む → 画面が揺れる |
| 連鎖 | 音程が階段を上がり、光と揺れが 1 段ずつ強くなる（頭打ちあり。眩しすぎると読めない） |
| 3個以上まとめて消える | 直前に 0.1 秒だけ止める（タメ）。止めてから解放すると同じ演出でも強く感じる |
| 選択中 | 白く脈動するアウトライン |
| ヒント（手順の上） | 黄色の脈動＋方向矢印（何も消さない手なら「これ自体は何も消えません（後につながる手）」と伝える） |
| ヒント（手順から外れている） | 「最短手順から外れています」とオーバーレイで伝え、やり直すか続けるかを選ばせる |
| クリア | 星が1つずつ跳ねて出る |

### サウンド ― 乾いたウッドクリックと、砕けるガラス

音色は 2 種類しかありません。

- **ウッドクリック**：掴む・滑る・着地する・UI を押す ―― **操作すべて**。帯域を絞ったノイズの一撃（木を叩いた芯）＋ 上から落ちてくる基音（詰まった鳴り）＋ 4 倍音を少しだけ（マリンバの丸み）。全部これになることで、プレイがリズムになります
- **グラスシャター**：消えた瞬間だけ。非整数倍（`1, 2.41, 3.86, 5.62, 7.71, 9.94`）の部分音を少しずつ遅らせて散らす。整数倍だと「鐘」に、非整数倍だと「ガラス」に聴こえる

連鎖するとウッドクリックの音程がペンタトニックの階段を上がっていきます。**「次はもっと高い音を聴きたい」**という欲求が、そのまま次の一手を探す動機になります。ハプティクスは音を出す関数の中で一緒に鳴らすので、指と耳がずれません。

> 実装上の補足：iOS/Safari は WebAudio だけを鳴らしていると音声セッションが「環境音」扱いのままで、消音スイッチで黙るうえ、**画面収録しても動画が無音になります**。ほぼ無音の WAV を `<audio>` でループ再生し続けてセッションを「メディア再生」に上げ、同じセッションを共有する WebAudio の出力が収録に乗るようにしています。

### 見た目 ― 色だけを主役にする

ブロックには**影も光沢も模様も乗せません**。一色のベタ塗りに、ほんのわずかな角丸だけ。マス同士のすき間は1〜2pxしか空けないので、盤面はタイルを敷き詰めたモザイクのように見えます。

同じブロックのマス同士は継ぎ目なく繋がり、すき間が入るのは別のブロックとのあいだだけ。だから**「どこまでが一緒に動くか」は形で読めます**。後ろの盤面も同じ考えで、淡い色のマスを同じ寸法・同じすき間で敷き詰めただけの平らな面です。

ダークモードは持ちません。端末の設定に関わらず**ブロックの色が同じに見えること**を優先しています ―― 色そのものが情報である以上、配色が2種類あることは利点より欠点が大きいと判断しました。

色の並びは**色相角ではなく Lab 空間の距離（ΔE）**で決めています。上のレベルでは12色が同時に盤面に出るので、似た色が並ぶとそれだけで詰む。色相を等間隔に並べても解決しません ―― 緑は90°〜160°がまとめて「緑」に見えるのに対し、赤〜橙は数十度でも別の色に見えるからです。「すでに選んだどれからも遠い色」を順に選ぶ並びにしたところ、12色での最小ΔEが15から31になりました。並びは先頭からN個取っても互いに離れているので、3色でも12色でも見分けがつきます。それでも足りない人のために「色に記号を付ける」設定があります。

盤面は画面幅の **90%** を占めます。左右の余白は詰め、進捗バーのような飾りは置かない。**視覚的なノイズを排除して、読むべきものを盤面だけにする**ためで、その結果として消えた瞬間の光がいちばん強く効きます。

### Liquid Glass ― 浮いている面だけがガラス

盤面はフラット、その上に浮く UI（ツールバー・シート・ボタン・チップ）だけが Z 軸の階層を作ります。ガラスの処方は全面で共通です。

- 背景を大きくぼかし、彩度を上げる（`blur(34px) saturate(200%)`）。後ろの色を吸って、ガラス自体がうっすら色づく
- 縁は 2 本 ―― 上端に白い光の線、全周に極薄の暗いヘアライン。白の上でも黒の上でも輪郭が消えない
- 上面の照り返しは要素の `background` に敷く。オーバーレイを重ねないので、文字の上に膜が乗らない

ホーム画面にだけ、ブロックの4色をごく淡く広げた光を敷いてあります。**ガラスは「後ろに何かある」ときにしか美しくならない**ためで、その上にガラスのボタンを置くと、背景の色を拾って縁が色づきます。

## 8. 難易度を構成する要素

難易度は**厳密な最短手数ひとつ**で測っています。他の指標（盤面サイズ・埋め率・灰色の数）は、その手数を作るための**材料**であって、難易度そのものではありません。実際、盤面を広げると手数はむしろ縮みます。

材料として効くのは次の3つです。

- **灰色の形と配置**：数と形が「通路の迷路」を決める。いちばん効く材料
- **埋め率**：詰まっているほど動かせる方向が減り、遠回りが必要になる。ただし詰めすぎると動けなくなって逆効果
- **盤面サイズ**：小さいほうが逃げ場がなく、手数が伸びやすい

これらを振って候補を作り、**出てきた最短手数で並べ替える**のが `tools/levels.mjs` です。狙って難易度を作るのではなく、作ってから測って並べる ―― 出てくる手数が前もって読めない以上、これがいちばん正直なやり方でした。

「読みの深さ」を測る指標として、`npm run verify` は**最長の無消去連続**（手順の中で何も消えない手が最大何手続くか）を出します。色つきが1組しかないので、これは常に「最短手数 − 1」―― いちばん上のレベルなら **83手ぶん滑らせ続けて、やっと消えます**。

## 9. 位置づけと独自性

| ゲーム | 移動 | 消去 | 重力 |
|---|---|---|---|
| テトリス | 落下・回転 | ライン揃え | あり |
| ぷよぷよ | 落下 | 同色4連結 | あり（連鎖） |
| SameGame | クリック | 同色連結 | あり |
| Rush Hour | スライド | なし | なし |
| アイススライド系 | 決定論的スライド | なし | なし |
| **SLIDE POP!** | **決定論的スライド** | **同色ペア接触** | **なし** |

本作は**「アイススライドの決定論性」×「接触消去」×「重力なし（空間が資源）」**という、それぞれ実績のある mechanic の未踏の交差点に位置しています。特に「消去が通路を生み、通路が消去を可能にする」という**循環構造**は、重力型パズルにも純スライドパズルにも存在しない、本作固有のものです。

そのうえで本作は、**消去そのものを遠ざけました**。色つきの2個は1手ではぶつからず、ぶつけに行く道のりを何十手も組み立てる必要がある。盤面の大半を占める灰色は消えないので、**通路は自分で並べ替えて作る**しかありません。結果として、アイススライド系の「1本の折れ線を読む」楽しさと、接触消去系の「盤面のトポロジーが書き換わる」楽しさが、1つの手番の中で重なります。

## 10. 拡張の方向性

- **デイリーパズル**：その日のレベルを全プレイヤー共通に・タイムのランキング
- **リプレイ共有**：解の手順をシリアル化して共有・検証可能に
- **追い込みの可視化**：ヒントを「1手目」ではなく折れ線そのもので見せるモード（初級者向けの補助輪）
- **別解を許すヒント**：いまは最短手順1本との照合なので、同手数の別ルートも「外れ」と判定される。全配置の距離マップごと焼き込めば解消できる
- **レベルの追加**：いまは60レベル。`tools/levels.mjs` の数字を増やせばそのまま伸ばせる
- **実装済み**：**厳密な最短手数によるレベル分け**（60レベル、2〜84手）、焼き込みデータによる全端末共通の譜面、**鍵の無いレベル選択**、**解決時間による星評価と自己ベスト**、**最短手順の上でだけ出るヒント**、**端末データの消去**

---

**総括**：SLIDE POP!は「空きマスという負の空間を、消去によって稼ぎ、滑走によって消費する」ゲームです。ルールは3つしかないのに、盤面のトポロジーが手ごとに書き換わることで、深い再帰的計画が生まれます。

そして**同色ペアは、はじめから隣り合ってはくれない**。初手からすでに、目の前に押せる手はありません。スライドにスライドを重ねて、ぶつける場所まで運ぶ道筋を、頭の中で組み立てるしかない。星が手数ではなく時間で決まるのは、**測りたいものがまさにその「読んでいた時間」だから**です。

生成アルゴリズムが「解けること」を構造的に保証するため、プレイヤーは常に「自分が悪かった」と納得できる――純粋パズルとして最も大切な信頼関係を、設計の土台から持っているゲームです。
