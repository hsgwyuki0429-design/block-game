# SLIDE POP!

**凍った盤面を滑らせて、同色をぶつけて、盤面を空にする。**

ほぼ埋め尽くされた盤面。ブロックは押せば壁にぶつかるまで一直線に滑る。同じ色のブロック同士が触れれば弾けて消え、消えた跡には「空きマス」という通路が生まれる。重力も連鎖もない。あるのは **「空きマスこそが唯一の道具」** という事実だけ。

レベル1から無限に続くレベル制。依存パッケージゼロのバニラ JavaScript（Canvas + WebAudio）製。

```
npm start          # http://localhost:8080 で遊ぶ
npm run build      # src/ から app.js を生成（src/ を編集したら必ず実行）
npm test           # ルール・生成器・レベル進行・配信物のテスト（48 件）
npm run verify     # レベル 1〜80 をすべて生成して検証し、統計を出す
```

`index.html` を `file://` で直接開いても動きます。

## ルールは 3 つだけ

| | ルール | 意味 |
|---|---|---|
| ① | **スライド** | できるのは「どのブロックを、どの方向に押すか」だけ。壁か他のブロックにぶつかるまで滑り続ける。**距離は選べない** |
| ② | **同色接触消去** | 滑り終えた直後、上下左右で同色が触れていれば繋がったグループ全体が消える。消去の単位は「ブロック」で、**単体は自己消去しない**（＝必ず 2 個以上・8 セル以上） |
| ③ | **重力なし** | 消えても他は落ちない。**空きマスは消去でしか生まれず**、生まれた空きマスが次のスライドの通路になる |

- **勝利**：盤面のブロックを全て消す
- **詰み**：どう動かしても同色接触を作れない状態。運ではなく手順の帰結なので、Undo は常にフェア

## レベル ― 1 から無限に

レベル1は 4×4 にテトロミノ2個、PAR 1手。ここから少しずつ広く・複雑になっていきます。

| 変わるもの | 進み方 |
|---|---|
| **盤面** | レベル1で 4×4。レベル 3・5・7・10・13・17・21・26 でそれぞれ1マス広がり、**レベル26で 12×12（上限）** |
| **ブロック** | レベル12までは素のテトロミノ。以降 **テトロミノ2個つなぎ**（8セル）が混ざりはじめ、レベル24で全部2個つなぎに。レベル26から **3個つなぎ**（12セル）が現れ、**レベル46で全部3個つなぎ**。以降はずっと3個つなぎ |
| **色数** | 小さい盤面は3色。広がるにつれて6色まで |

連結ピースは「テトロミノを辺でつないだ形」に限定しているので、大きくなっても *テトリスのブロックの合体* として読めます。ブロック内部には元のテトロミノ同士の**継ぎ目**が薄く描かれ、何個つなぎなのかが一目で分かります。

**レベル番号 → シード → 決定論的な生成** という一本道なので、**同じレベルなら、どの端末でも必ず同じ盤面**です。URL のハッシュ（`#L26`）でレベルを直接開けます。

レベルが上がるほど1ブロックが大きくなるぶん、盤面に載るブロック数と手数（PAR）は減ります ―― 終盤は「少数の巨大な剛体を、狭い隙間でどう滑らせるか」という別種の難しさに変わります。

`npm run verify` で測ったレベル 1〜80 の実測値：

| レベル | 盤面 | ブロック | 埋め率 | PAR | 個数 |
|---|---|---|---|---|---|
| 1 | 4×4 | 4セル | 50% | 1 | 2 |
| 8 | 7×7 | 4セル | 82% | 5 | 10 |
| 12 | 8×8 | 4セル | 75% | 6 | 12 |
| 20 | 10×10 | 4/8セル | 80% | 7 | 15 |
| 26 | 12×12 | 8セル | 67% | 6 | 12 |
| 40 | 12×12 | 8/12セル | 61% | 4 | 8 |
| 50〜 | 12×12 | 12セル | 58〜67% | 3〜4 | 6〜8 |

## 見た目と手触り

**UI は退き、粘土のブロックだけが前に出る。** iOS 26 の Apple Music に倣った作りにしている。

- **無彩色の背景** ― ライトは白、ダークは黒。色を持つのはコンテンツ（盤面のブロック）だけで、それ以外は状態を伝えるときにしか色を使わない
- **大きなタイトル** ― 左上に「レベル 12」を 34px / ウェイト800 / トラッキング -0.03em で置き、その下に薄いグレーの補足（盤面サイズ・ブロック構成・色数）。書体は SF（`-apple-system`）、日本語はヒラギノ角ゴ
- **下に浮くガラスのツールバー** ― 戻す／ヒント／やり直すのピルと、レベル選択の**独立した丸ボタン**。位置は `fixed` で、盤面はその下を通り、ガラス越しにぼけて透ける
- **カプセル型のセグメント** ― 手数・PAR・残りは丸いカプセルに。色チップも同じ言語
- **設定は iOS のリスト** ― 角丸のグループ、文字の頭から始まる細いインセット区切り線、iOS 風トグル。モーダルは下から出るシート（グラバー付き、広い画面では中央のカード）
- **ブロック（織物）** ― 濃紺の台の上に、毛糸を編んだようなタイルを並べる。斜め45度に走る糸の目をマスの大きさに合わせて生成し、overlay で色の上に乗せる。上のふちが光り下のふちが翳る立ち上がりは、輪郭を上下にずらして描いてクリップで内側半分だけ残す方法で作っている。**すべてのマス境界に細い溝**を彫って「1マスずつ縫い合わせた布」に見せ、連結ピース（2個つなぎ・3個つなぎ）の境目だけ溝を強くして、何個つなぎのブロックなのかが読めるようにしている
- **ライト／ダーク両対応**、`prefers-reduced-motion` を尊重、色に頼らない情報伝達（色記号のオプション、残り1個の色は縁取りで警告）

### 消える瞬間を祝う

| 行為 | 反応 |
|---|---|
| ブロックを掴む | 小さなティック音 |
| 滑って壁にぶつかる | マリンバのような丸い着地音（距離が長いほど低い）＋ 進行方向へのつぶれ |
| 消える | **音程が連鎖ごとに階段状に上がる**破裂音（ペンタトニック）＋ 布のかけらが飛び散る ＋ 白いフラッシュ ＋ 拡散リング ＋ 画面の揺れ |
| 3個以上まとめて消える | 消える直前に **一瞬止まる（タメ）**。止めてから解放すると同じ演出でも強く感じる |
| 大量消去 | 「○個消し！」の浮き文字＋段階評価（12個=グレイト、16個=ファンタスティック、20個=ミラクル）＋ 連鎖数 |
| 動かせない方向 | ブロックが小刻みに揺れて拒否＋低い短音（手数には数えない） |

効果音は音源ファイルを持たず、WebAudio でその場で合成している（`src/audio.js`）。連鎖が続くほど音が上がっていくので、「この連鎖を切りたくない」という気持ちが自然に生まれる。iOS は最初のタップまで音を出せないので、最初のポインタ操作で解錠している。

### 面白さの正体

消去は盤面のトポロジーそのものを書き換える。1 つ消えることで届かなかった場所へ届くようになり、止まっていた位置が意味を失う。**「どの順番で消すか」が「何を消せるか」を決める。**

最も気持ちの良い手は **橋渡し** ―― 離れた 2 つの同色グループの間にブロックを滑り込ませ、3 つ以上を一度に繋いで消す手。ルール上、消えるグループは必ず「動かしたブロック」を経由して繋がる（動かしていない同色同士は不変条件により決して隣接しない）。動くブロックは常にハブになる。この星型構造が見えた瞬間、盤面の見え方が変わる。

## 「解ける盤面」を構造的に保証する

ランダムに埋めて解けるか検証する、という素朴な方法は使っていない（高密度の盤面はほぼ確実にデッドロックを含み、検証コストも爆発する）。代わりに **「解の逆順構築」** を採用している。

**盤面を作って解くのではなく、解を作って盤面を導く。** 完成状態（空盤面）から出発し、「ある 1 手でまとめて消えるブロック群」を 1 ステップずつ置いていく。最後に置いたステップが、解の第 1 手になる。

```
S_N = ∅（空盤面）← ステップ1 ─ S_{N-1} ← ステップ2 ─ … ← ステップN ─ S_0（初期盤面）
```

各ステップで置くもの：

- **移動ブロック P**：色 c・形状・着地点 B・滑走方向 d・開始点 A (= B − t×d)
- **相棒ブロック Q₁..Qₘ**：同色 c。それぞれ B の P に隣接し、Q 同士は非隣接

配置時に課す制約と、それが保証する性質：

| 制約 | 保証する性質 |
|---|---|
| 新規セルはすべて空きマス | ブロックの重複なし |
| 既存の同色ブロックと隣接しない | 初期盤面の同色隣接ゼロ ＋ 各手で「予定外の巻き込み消去」が起きない |
| A→B の経路が空、B+d に壁かブロック | その手が実際に実行可能で、ちょうど B で止まる |
| A に居る時点で同色接触していない | 中間状態の不変条件が保たれる |

### なぜ不変条件が効くか

どの手の直後も「同色ブロック同士は隣接していない」状態が保たれる（触れた瞬間に消えるため）。この不変条件があるからこそ **「動かしたブロックが触れた相手だけが消える」** ことが確定し、逆順構築の各ステップを独立に検証できる。

この方式の副産物として、**PAR（保証解の手数）とヒント機能がほぼ無償で手に入る**。解そのものがデータとして存在するからだ。

レベルごとに変わるのは「使うブロックの形状集合」「盤面サイズ」「色数」「目標の埋め率」だけで、構築の仕組みは共通です。1ステップごとにブロックのクラス（テトロミノ / 2個つなぎ / 3個つなぎ）を配合比で抽選し、そのクラスだけでそのステップを組みます ―― 1ステップ分のブロックはまとめて消える仲間なので、形を揃えると見た目のまとまりも良くなります。

`npm run verify` はレベル 1〜80 をすべて生成し、解答手順を実際に実行して本当に全消しできることを確かめます：

```
失敗            : 0
埋め率          : 平均 63.6%（レベルが上がりブロックが大きくなるほど下がる）
PAR             : 平均 4.2 (1〜8)
生成時間        : 中央値 65ms / 90%点 637ms / 最大 1.5s
```

生成に時間がかかるレベル（12×12 に12セルのブロックを詰めるとき）があるので、ゲーム側は**非同期版の生成器**を使い、試行の合間にイベントループへ制御を返しながら「組み立て中」を表示します。画面は固まりません。

## 操作

| 操作 | 動作 |
|---|---|
| ブロックをスワイプ | その方向へスライド（26px の閾値を超えた瞬間に発動） |
| ドラッグ中 | **着地予測ゴースト**と矢印を表示。消える相手は黄色く光る |
| クリック → 矢印キー | 精密操作・キーボード派向け |
| `Z` / `H` / `R` / `L` | 戻す / ヒント / やり直す / レベル選択 |

動かせない方向へスワイプするとブロックが小刻みに揺れて拒否する（手数には数えない）。

盤面上部の色チップは色ごとの残りブロック数で、残り 1 個の色（＝相棒がいない色）は白く縁取られる。

進捗と自己ベストはブラウザに保存され、次に開いたとき前回のレベルから再開する。URL のハッシュ（`#L26`）でレベルを直接開ける。

## 構成

```
index.html          画面（app.js?v=<ハッシュ> を読む）
styles.css          UI スタイル（ガラス・シート・ライト/ダーク）
app.js              tools/build.mjs が src/ から生成する配信物。直接編集しない
src/
  rng.js            シード付き乱数（mulberry32）
  shapes.js         テトロミノ7種の全回転（19 向き）＋ テトロミノ連結ピースの生成
  levels.js         レベル定義（盤面サイズ・形状の配合比・色数・シード）
  board.js          盤面モデルとルール（スライド / 同色グループ / 消去 / 詰み判定）
  generator.js      解の逆順構築によるパズル生成 + 解答手順の検証
  render.js         Canvas 描画（織物ブロック・継ぎ目・ゴースト・粒子・フラッシュ）
  audio.js          WebAudio で合成する効果音（音源ファイル不要）
  input.js          スワイプとクリック選択
  game.js           進行・アニメーション・Undo・ヒント・レベル管理・UI 配線
  main.js           起動と URL ハッシュの解釈
tests/              ルール・生成器・レベル進行・配信物のテスト（node --test）
tools/build.mjs     src/ を app.js に束ねてハッシュを刻む
tools/verify.mjs    レベルの大量検証と統計
server.mjs          依存ゼロの静的サーバ
```

ルールの実装（`src/board.js`）とパズル生成（`src/generator.js`）はブラウザ API に一切依存していないので、Node からそのままテストできる。

### 実装上のメモ

- **詰み判定は 2 手先まで見る。** 仕様上の敗北条件は「どの手でも同色接触が起きない」だが、それだけだと「消去しない手で通路をずらし、次の手で消す」という正当な組み立てを誤って敗北にしてしまう。消去手が 2 手以内にひとつも無いときだけ詰みとしている。
- **ヒントは 2 段構え。** 現在の局面が保証解の道筋上にあれば（局面の指紋で照合）その手を、外れていれば「いま最も多く消せる手」を示す。
- **埋め率は詰め込み優先度で稼ぐ。** 逆順構築で開始点 A を選ぶとき、壁や既存ブロックに接している配置から順に試すことで空きマスの断片化を防ぎ、74% → 81% まで埋め率が上がった（テトロミノの 12×12 の場合）。
- **連結ピースはレベルごとに作り置きする。** テトロミノ3個つなぎの形は膨大にあるので全列挙はしない。レベルのシードから数種類だけ生成し、その全回転をそのレベルの形状集合とする。結果としてレベルごとに固有の「手触り」が出る。
- **ブロックは外周だけを縁取る。** セル矩形の集合をそのまま stroke すると内部のセル境界にも線が出て、レベル1のようにセルが大きい盤面では1個のブロックが格子模様に見えてしまう。外周の辺と外側の角だけを集めた Path2D を別に作って使っている。
- **配信物は 1 本に束ねる。** `index.html` と `src/*.js` を別々に配信すると、ブラウザが「新しい HTML ＋ 古い JS」を組み合わせてしまうことがある（GitHub Pages はどちらも短い max-age で配信し、Safari は JS を長く保持する）。実際にそれで盤面が真っ白になった。`app.js?v=<内容ハッシュ>` に束ねれば HTML と JS が食い違いようがなく、`file://` でも動く。生成物が古いままにならないよう、`npm test` が最新かどうかを検査する。
- **`roundRect` は自前でも用意する。** Safari 16.4 未満に無いので、無ければ `CanvasRenderingContext2D` と `Path2D` に足している。
