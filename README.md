# SLIDE POP!

**滑らせて、ぶつけて、盤面を空にする。**

ブロックは押せば壁にぶつかるまで一直線に滑る。同じ色のブロック同士が触れれば弾けて消え、消えた跡には「空きマス」という通路が生まれる。重力も連鎖もない。あるのは **「空きマスこそが唯一の道具」** という事実だけ。

盤面にあるのは **色つきのブロック 1 組と、消えない灰色のブロック**。やることは「その 1 組をぶつける」だけ ―― ただし **2 個は、はじめから隣り合ってはくれません。** 灰色が通路を塞いだ盤面を縫って、ぶつけられる場所まで運ぶ。レベル1は 2 手の練習問題ですが、レベル1000 では **300 手**かかります。

その手数は推定ではありません。**到達できる盤面を全部展開し、ゴールからちょうど N 手の配置を初期盤面に選んでいる** ので、表示している手数は**厳密な最短手数**です ―― これより短い解き方は存在しません。

**レベルに上限はありません。** 1000 レベルぶんを焼き込んであり、その先はいちばん上の帯を繰り返します。

レベル1から無限に続くレベル制。**レベルに鍵はありません** ―― どこからでも、いつでも始められます。依存パッケージゼロのバニラ JavaScript（Canvas + WebAudio）製。

```
npm start          # http://localhost:8080 で遊ぶ
npm run build      # src/ から app.js を生成（src/ を編集したら必ず実行）
npm run icons      # ホーム画面用アイコンを生成（tools/icons.mjs）
npm test           # ルール・全探索・レベル進行・ランキング・素材・配信物のテスト（102 件）
npm run verify     # 焼いてある 1000 レベルを検証し、統計を出す

node tools/harvest.mjs --seconds 1800 --shard 0 --shards 4   # 盤面の採集（並列可）
node tools/remine.mjs                                        # 在庫の掘り直し
node tools/levels.mjs  --levels 1000                         # 手数カーブに流し込んで焼く
```

`index.html` を `file://` で直接開いても動きます（Service Worker だけは無効）。

**スマホのホーム画面に追加すると、全画面で起動し、通信が無くても遊べます。**

## ルールは 3 つだけ

| | ルール | 意味 |
|---|---|---|
| ① | **スライド** | できるのは「どのブロックを、どの方向に押すか」だけ。壁か他のブロックにぶつかるまで滑り続ける。**距離は選べない** |
| ② | **同色接触消去** | 滑り終えた直後、上下左右で同色が触れていればその 2 個が消える。列を揃える必要はない。**単体は自己消去しない** |
| ③ | **重力なし** | 消えても他は落ちない。**空きマスは消去でしか生まれず**、生まれた空きマスが次のスライドの通路になる |

盤面のほとんどは**灰色のブロック**で、これは**何と触れても消えません**。押せば同じように滑るので、**動く壁**として扱います。

- **勝利**：色つきの 2 個をぶつける（灰色は最後まで盤面に残ります）
- **敗北条件は無い** ―― 消せる手が見当たらない局面こそが普通の状態です。何も消さない手で通路を作るのが本筋。詰まったら `戻す` と `やり直す` がいつでも使える（時間の罰もありません）

滑って止まった直後は、同じ方向へはもう進めない。だから **ブロックの道のりは必ずどこかで曲がります**。

## 3 つの画面

| 画面 | 中身 |
|---|---|
| **ホーム** | 「ゲームスタート」（＝いま挑戦中のレベル）と「レベル一覧」。クリア数・星の総数・到達レベルを表示 |
| **レベル一覧** | 30 レベルずつのページ送り。**どのセルもいつでも押せる。**クリア済みには取った星と自己ベスト手数が並ぶ |
| **ゲーム** | 盤面と、タイム／手数、下に浮くツールバー（戻す／やり直す／ランキング） |

**レベルに鍵はかかっていません。** レベル1から順に上がってもいいし、いきなりレベル50 を開いてもいい。1つ詰まったら先へ行って、あとで戻ってくればいい ―― どのレベルも独立した1問なので、順番に意味はありません。進行状況（到達レベル・星・自己ベスト手数）はブラウザに保存されます。**設定シートの「この端末のデータを消す」**で、いつでも初期状態に戻せます ―― 取り返しがつかないので、1 回目のタップでは「何を失うか」を数字で見せ、もう一度押して初めて消えます（5 秒で解除）。

> 鍵をやめたのは、**詰まったプレイヤーに逃げ場が要る**からです。このゲームは1問が長く、読み違えると手が止まる。そこで唯一の道が「同じ問題をもう一度」しか無いと、ゲームが終わってしまう。別のレベルを触ってから戻ると、たいてい見えていなかった線が見えます。

### 星は「何手で解いたか」で決まる

| 星 | 条件 |
|---|---|
| ★★★ | **最短ちょうど** |
| ★★ | 最短の 1.5 倍 + 2 手まで |
| ★ | クリア |

基準になるのは見出しの下に出る「最短◯手」で、これは**厳密な最短手数**です。だから **★★★ は「最短で解いた」という、あいまいさのない達成**になります ―― それより短い解き方は存在しないと分かっているので、上振れの余地がありません。silver に +2 の余裕があるのは、2 手のレベルで 1 手ずれただけで ★1 まで落ちるのを避けるためです。

いま星いくつぶんの位置にいるかは、画面上の**手数**の色で分かります（★★★ を過ぎると黄、★★ も過ぎると赤）。

**`戻す` を押せば手数も戻ります。** だから迷ったら遠慮なく戻して構いません ―― 罰があるのは「無駄な手を確定させたとき」だけです。タイムも表示していますが、星には一切関わりません。

星と自己ベスト（最少手数）はレベルごとに最高記録だけが残り、レベル一覧に表示されます。

## レベル ― 1 から無限に、どこからでも

盤面には **色つきのブロックが 1 組（2 個）だけ**。残りはすべて**灰色**で、どの色とも消えません。やることは「その 1 組をぶつける」―― たったそれだけなのに、灰色が通路を塞いでいるせいで、レベル1000 では **300 手**かかります（レベル1 は 2 手の練習問題）。

| 変わるもの | 進み方 |
|---|---|
| **最短手数** | Lv1 → 2手 ／ Lv20 → 20手 ／ Lv50 → 40手 ／ Lv100 → 80手 ／ Lv500 → 100手 ／ Lv800 → 122手 ／ Lv950 → 162手 ／ **Lv1000 → 300手** |
| **盤面** | 4×4 〜 8×8。**広いほど難しいわけではない** ―― 詰まった小さい盤面のほうが手数は伸びる |
| **空きマス** | 2〜6 マス。ブロックがぎっしりで、動かせる方向自体が少ない |
| **ブロック** | 色つきも灰色も 1×2 〜 3×3 の長方形。大きいほど通れる隙間が減る |

難易度は色数でも盤面の広さでもなく、**厳密な最短手数そのもの**でつけています。上の折れ線（`src/levels.js` の `PAR_ANCHORS`）が目標で、**その手数になる盤面を探して**割り当てています。

前半は一気に、中盤はゆっくり、そして**最後の 25 レベルで跳ね上がります**。上端を切り立たせているのは、深い盤面の出方がそうなっているから ―― 110 手級なら 4 コアで毎分 2 枚採れますが、**300 手級は 1 時間に 2 枚**です。数百レベルぶんは揃いませんが、数十レベルぶんなら揃う。

この折れ線は**採れた深さの実測に合わせてあります**。願望で引いても、そこに置く盤面が無ければ意味がない ―― 上端の形は探索の当たり方がそのまま決めています。

レベル975〜1000 は 192 手から 300 手へ、1 レベルごとに 4 手以上。この帯は**どのレベルも手数が違い、盤面も全部別物**です。

> **なぜ 1 組だけなのか。** 色を増やしても最短手数は伸びませんでした。同色ペアが n 組あると、最短解は「n 組のうち **いちばん近い 1 組**」から決まってしまい、実測で **色数 × 1.8 手**からどうやっても動かない。灰色を混ぜても、形を変えても、埋め率を上げても同じでした。伸ばすには色を減らして**その 1 組を遠ざける**しかない ―― それが下の「厳密生成」です。

### 厳密生成 ― 欲しい手数の盤面を、名指しで取り出す

**混ぜて作るのをやめました。** 以前は完成状態から手順を逆再生してブロックを置いていましたが、それでは「解ける手順が 1 本ある」ことしか保証できません。実際には**ずっと短く解けてしまい**、PAR 106 手と表示していた盤面が 20 手で終わることさえありました。

いまは逆で、**その盤面で到達できる配置を全部展開します**（`src/exact.js`）。

1. 色つき 2 個を**くっついた状態**（＝ゴール）で置く
2. 灰色の長方形で、**空きマスがちょうど N マス**（2〜6、いちばん深いのは 3）になるまで盤面を埋める
3. そこから指せる手を**幅優先で展開し、到達できる配置をすべて列挙する**
4. 「くっついている配置」全部を距離 0 として**逆向きの幅優先探索**を回し、全配置について**ゴールまでの最短距離**を出す
5. **距離がちょうど N の配置**を初期盤面に採る。N がそのままそのレベルの最短手数になる

状態空間を丸ごと見ているので、出てくる手数は推定ではなく**厳密な最短手数**です。**これより短い解き方は存在しません。**

**5 が新しいところです。** 以前は「いちばん遠い配置」だけを採っていたので、出てくる手数は運任せでした ―― 欲しい手数を狙えない。ところが 4 の距離マップには **0 手から最遠まで、全部の距離が入っています**。だから「ちょうど 300 手の配置を出せ」と名指しで頼めます。レベル1000 本ぶんの手数カーブを埋められるのはこれがあるからです。

### 1 枚の盤面から取るのは、1 問だけ

距離マップは 1 枚から何十問でも切り出せます。切り出したものは灰色の位置まで違う（配置には灰色の座標も入っている）ので、一見すると別の問題です。

**それでもやりません。** ブロックの顔ぶれ ―― 2×3 が 2 個、3×3 が 1 個、1×2 が 4 個… ―― が同じままなので、並べて遊ぶと「さっきと同じ盤面」に見えてしまう。実際に 1 枚から最大 34 レベルを切り出した版を作ってみたところ、1000 本中 979 本が使い回しになりました。

いまは **1 枚の盤面につき 1 レベルだけ**。1000 レベルは 1000 枚の別々の盤面から取っています。採集の効率は落ちますが（深さ 363 の盤面を引いても 1 問しか取らない）、そこは探索時間で払っています。

> **切り捨てたぶんは、あとで掘り直せます。** 上限が 110 手だった頃の在庫を調べ直したら、深さ 363・272・243 の盤面が眠っていました ―― 目標が 110 手だったので、そこで切って捨てていたのです。`tools/remine.mjs` は在庫の手順を最後まで指してゴール状態に戻し、そこから探索し直して本当の深さを測ります。1 枚 0.25 秒で、探し直すより桁違いに速い。上端を 300 手へ引き上げたときは、これだけで不足の 7 割が埋まりました。

### 灰色の 2 マスブロックは、少ないほうを選ぶ

1×2・2×1 の小さい灰色が並ぶと、盤面が細切れに見えて**どこが通路なのか読みにくく**なります。減らしたい ―― のですが、これが厄介で、**2 マスは深い盤面に構造的に必要**でした。華容道の「縦棒」と同じ役で、大きい塊の隙間を通り抜けて場所を入れ替えるのがこれの仕事です。

6×6・空き 3 マスで、灰色の出方だけを変えて 4 分ずつ測った結果：

| 灰色の出し方 | 深さ110以上 | 到達した最深 | 2 マスの割合 |
|---|---|---|---|
| 全種類を等しく | 1.25 枚/分 | 131 | 67% |
| **2 マスを半分に** | **3.00 枚/分** | **332** | **60%** |
| 2 マスを 1/4 に | 0.50 枚/分 | 147 | 51% |
| 2 マスを禁止 | 0 枚/分 | 90 | 0% |

**禁止すると盤面が動かなくなり、手数が伸びません**（そもそも空き 3 マスぴったりに詰められず、組み立て自体が 14 万回失敗しました）。意外だったのは、**半分に減らすほうがむしろ深くなる**こと ―― 2 マスが多いと盤面がゆるくなって手数が縮むようです。

そこで採ったのは「禁止」ではなく **2 段構え**です：

1. 採集するときは 2 マスの重みを半分にする（見た目も深さも良くなる点）
2. 焼くときは、**同じ手数・同じ広さなら 2 マスの少ない盤面から**採る

2 の効き目は在庫の厚みで決まります ―― 目標の 3 倍ぶん集めておくほど、選べる幅が広がります。実際、在庫を 2292 → 3787 枚に増やしただけで **2 マスの割合は 63.9% → 49.4%**（1 盤面あたり 6.9 個 → 4.6 個）まで落ちました。

> **ただし追いすぎると別のものが消えます。** 2 マスを減らすことだけを追うと、大きい色つき（2×2 以上）の盤面が総取りで押し出され、在庫に 12% あるのに焼き上がりでは 1000 本中 1 本まで減りました。いまは**大きい色つきを「2 マス 3 個ぶん」の価値として扱って**釣り合いを取っています ―― 大きい色つきが 49 → 91 個に戻り、2 マスの割合は 52.5% → 53.1% とほぼ動きません。

### 盤面はできるだけ小さく

同じ手数なら、小さい盤面のほうが読みやすく、詰まった手触りも出ます。だから **4×4 で足りるなら 4×4、そこに在庫が無ければ 5×5、6×6 …と、必要になって初めて広げます**。

広げるのは好みの問題ではなく、**その手数が小さい盤面では出せないから**です。5×5 は 81 手あたりが天井で、110 手級は 6×6 以上でしか出ません ―― 上のレベルだけが自然に広くなります。

> **同じ形の灰色ブロックは区別しない。** ここを素直に実装すると、同じ形のブロックを入れ替えただけの配置が別物として数えられ、状態数が階乗で爆発します（6×6 で数十億）。形ごとに位置を並べ替えてから状態の鍵を作ると、同じ盤面は 1 つに畳まれ、数万まで落ちます。この一点で全探索が現実的になりました。

#### どこに深い盤面があるか

深さは盤面の広さでは決まりません。実測（1 分あたり、深さ 110 手以上に届いた盤面の数）：

| 盤面 | 空きマス | 到達した最大手数 | 110 手以上 |
|---|---|---|---|
| 5×5 | 2 | 36 | 0 |
| 5×5 | 3 | 81 | 0 |
| 6×6 | 2 | 65 | 0 |
| **6×6** | **3** | **156** | **4** |
| 6×6 | 4 | 115 | 1 |
| 7×7 | 3 | 139 | 2 |

**空きマス 3 の 6×6 が谷底です。** 空きが多いと配置が広がりすぎて全探索が終わらず（打ち切り）、少なすぎるとブロックが動けなくなって手数が落ちる。華容道（5×4・空き 2 マス）が 81 手かかるのと同じ構造で、**深い手数は「動かせる隙間が数マスしか無い」ときにしか出ません**。

採集側（`tools/harvest.mjs`）はこのレシピ表を固定で持たず、**走らせながら選び直します** ―― 序盤は短い手数がいくらでも足りるのでどのレシピも当たりますが、埋まってくると深い盤面を出せるレシピしか役に立たなくなる。「1 秒あたり何問採れたか」で重みを付け直す ε-greedy にしてあります。

#### 焼き込みと詰め方

盤面 1 枚を全部展開するのは数ミリ秒〜数十ミリ秒ですが、**110 手級の 1 枚を引き当てるには数千枚**要ります。あらかじめ生成して `src/levelData.js` に焼き込み、実行時はそれを読むだけにしています（1 レベルの組み立ては 1ms 前後）。

```
# 4 プロセス並列で採集（shard を変えるとシードが変わる）
node tools/harvest.mjs --seconds 2100 --shard 0 --shards 4
# 大きい色つきブロックのレベルも混ぜたいときは --color big / huge を足した shard も回す
node tools/harvest.mjs --seconds 600  --shard 9 --shards 4 --color huge
# カーブの上端を引き上げたら、在庫を掘り直して眠っている深さを起こす
node tools/remine.mjs
# 在庫を手数カーブに流し込んで焼く
node tools/levels.mjs --levels 1000
```

素直に JSON で書くと 300 手の問題は 1 本 6〜7KB ―― 1000 本で 4MB になり、アプリ本体の 20 倍という馬鹿げた大きさになります。そこで **1 レベル = 1 本の文字列**に潰しました（`src/levelCodec.js`）。潰せるのは盤面に出てくるものが少ないからです：

- ブロックは全部長方形で、幅も高さも 1〜3 マス ―― 形は 9 通り＝**1 文字**
- 盤面は 8×8 まで ―― 位置は 0〜63 で**1 文字**
- 色つきは必ず 2 個で必ず先頭 ―― **色を書く必要が無い**（3 個目以降は全部灰色）
- 1 手は「どのブロックを・どの向きへ・何マス」―― 向き 4 × 距離 7 で**2 文字**

#### 焼き上がり

**1000 レベル・233KB。1000 レベルが 1000 枚の別々の盤面**、目標カーブとのずれは平均 0.09 手。実測値：

| レベル | 盤面 | 埋め率 | 灰色 | ★★★（＝最短） | ★★ まで |
|---|---|---|---|---|---|
| 1 | 4×4 | 81% | 1 個 | 2 | 5 |
| 10 | 5×5 | 84% | 5 個 | 11 | 19 |
| 20 | 5×5 | 88% | 6 個 | 20 | 32 |
| 50 | 5×5 | 84% | 6 個 | 40 | 62 |
| 100 | 6×6 | 89% | 8 個 | 80 | 122 |
| 300 | 6×6 | 89% | 9 個 | 90 | 137 |
| 500 | 6×6 | 89% | 9 個 | 100 | 152 |
| 700 | 6×6 | 89% | 9 個 | 115 | 175 |
| 950 | 6×6 | 89% | 9 個 | 162 | 245 |
| 1000 | 6×6 | 89% | 9 個 | **300** | 452 |

手数の帯ごとの盤面の広さ ―― **小さいほうから使い、届かなくなって初めて広げている**のが見えます：

| 手数 | 本数 | 盤面 |
|---|---|---|
| 2〜39 | 49 | 4×4:5 5×5:44 |
| 40〜79 | 50 | 5×5:42 6×6:8 |
| 80〜99 | 390 | 5×5:6 6×6:384 |
| 100〜300 | 511 | 6×6:484 7×7:22 8×8:5 |

色つきの形は 1×2・2×1 が 1153 本といちばん多く、2×2 が 91 本、2×3・3×2 が 52 本、3×3 も 2 本あります。灰色のうち 2 マスのものは **49.4%**（1 盤面あたり 4.6 個）まで下がりました。

**レベル1001 以降は、いちばん上の 200 レベルをぐるぐる回します。** 頭に戻すと難易度が一気に落ちて「終わった」感じになるからです ―― レベル番号は上限なく続き、手数もいちばん上の帯のまま保たれます。**同じレベルなら、どの端末でも必ず同じ盤面**です（焼いてあるデータをそのまま読むだけなので）。URL のハッシュ（`#L426`）でレベルを直接開けます。

## 見た目と手触り

**UI は退き、ブロックの色だけが前に出る。** iOS 26 の Apple Music に倣った作りにしている。

- **明るい配色ひとつだけ** ― ダークモードは持たない。端末の設定に関わらず、ブロックの色が同じに見えることを優先している
- **盤面が主役** ― 画面幅の **90%** を盤面が占める。左右の余白は 12px まで詰め、進捗バーのような飾りは置かない。読むべきものは盤面だけ
- **大きなタイトル** ― 左上に「レベル 24」を 34px / ウェイト800 / トラッキング -0.03em で置き、その下に薄いグレーの補足（`6×6・最短84手・灰8個・埋め率89%`）。書体は SF（`-apple-system`）、日本語はヒラギノ角ゴ
- **設定は iOS のリスト** ― 角丸のグループ、文字の頭から始まる細いインセット区切り線、iOS 風トグル。モーダルは下から出るシート（グラバー付き、広い画面では中央のカード）

### Liquid Glass

浮いている面はすべて同じ処方でガラスにしている（`--glass-blur` / `--glass-edge` / `--glass-sheen`）。

- **背景を大きくぼかし、彩度を上げる**（`blur(34px) saturate(200%)`）― 後ろの色を吸って、ガラス自体がうっすら色づく
- **縁は 2 本** ― 上端に白い光の線、全周に極薄の暗いヘアライン。白の上でも黒の上でも輪郭が消えない
- **上面の照り返し**は要素の `background` に敷く（オーバーレイを重ねない）。文字の上に膜が乗らない
- **下に浮くツールバー** ― 戻す／やり直すのピルと、レベル一覧の独立した丸ボタン。`fixed` なので盤面はその下を通り、ガラス越しにぼけて透ける
- **ホームには淡い光を敷いてある** ― ガラスは「後ろに何かある」ときにしか美しくならないので、ブロックの4色をごく淡く広げ、その上にガラスのボタンを置いている

### ブロックの見た目 ― 素材は 7 つ

設定シートからいつでも切り替えられる（見た目だけが変わり、盤面もルールも一切変わらない）。

**既定は「プレーン」。** 厚みも面取りも影もテクスチャも持たない、色そのものの平らな面 ―― 目が拾うものが「色と形」しか無いので、どのブロックがどこまでかが一瞬で読める。素材は好みで選ぶ飾りで、遊べることのほうが先にある。

残り 6 つは、ブロックを「色の付いた板」ではなく**その素材で削り出した塊**として描く。**画像は 1 枚も使っていない。** すべて実行時に手続き的に描いている。

- **石** ― 磨いた御影石。面はほとんど平らで、石らしさは**粒**（明るい長石と暗い黒雲母を閾値で切って散らす）が持つ
- **木** ― 年輪をノイズで歪めて三角波で折り返し、導管の細い筋を重ねる。**木目は必ず長辺に沿う**（縦長のブロックにはタイルごと 90° 回して貼る）
- **金属** ― 片方向にだけ細かく振ったノイズでヘアラインを引き、帯状の映り込みを重ねる。面取りは留め継ぎ
- **クリスタル** ― 角を 45° で切り落としたエメラルドカット。8 面それぞれに別の明るさを与え、卓面は透かしてトレイを見せる
- **紙** ― 繊維と簀の目。ほとんど平ら（粗くすると漆喰になる）
- **布** ― 縦糸と横糸が市松に交差する平織り

#### 視認性が先、質感はその次

素材は**遊びやすさを損なわない範囲でしか**主張してよくない。ここは一度作り込みすぎて失敗している ―― 割り肌の石も 22 本の年輪も、拡大すれば見事だが、1 マスが 40px そこそこになると模様がブロックの輪郭と同じ細かさになり、**形が模様に埋もれて読めなくなった**。

いま守っているのは 3 つ。

- **模様は地の上に薄く重ねる**（素材ごとの `grain`）。不透明で敷かない
- **模様の粒は大きく、数は少なく**。年輪は 1 タイルに 4 本、石は凹凸ではなく粒だけ
- **盤面はブロックよりはっきり暗い**。明るいブロックが暗い受け皿に載っている、という関係が輪郭をいちばん強く立たせる（テストで明るさの差を 40 以上に固定してある）

#### 立体は 1 本の経路で組む

素材が受け持つのは**表面だけ**。立体の組み立ては `src/render.js` の 1 本道が全部やる ―― 素材ごとに立体の作りを分岐させると、素材を足すたびに立体が壊れる。

```
接地影 → 側面の厚み → 天面のテクスチャ → 面取り → 縁の線
```

素材はこの経路に「厚み・面取りの幅・角の丸み・すき間・艶・影の濃さ」を**マスの一辺に対する比**で渡す。盤面が 4×4 でも 8×8 でも、同じ割合で見える。

#### 陰影は色ではなく「傾き」から作る

素材ごとに**高さの場**を作り、その傾きと光の向きの内積を明るさにする（バンプマッピング）。色を塗り分けただけのテクスチャは、動かすと平らに見える ―― 傾きから光を当てると、同じデータでも凹凸として読める。

傾きは**二乗平均で正規化**してある。細かい素材ほど傾きは大きくなるので、生の値を明るさにすると金属のヘアラインだけが白と黒に振り切れた。正規化すれば「どれくらい凸凹に見せたいか」という 1 つの数字だけで調整できる。

光は**全素材で同じ向き**（左上やや上）。素材ごとに光源が動くと、盤面が 1 つの場所に見えない。

#### 継ぎ目を出さないための約束

テクスチャは 256px のタイルを繰り返して敷く。ここは**間違えると盤面に格子の線が走る**ので、約束を 3 つ守っている（3 つとも、破って実際に線が出た）。

- **ノイズの周回数は整数**。整数でないとタイルの左端と右端が別の値になる
- **拡大縮小を掛けたまま `createPattern` を敷かない**。継ぎ目に半端な画素が挟まる。実寸に焼き直してから等倍で敷く（焼き直すときも、周囲に回り込んだ余白を付けてから中央を切り出す）
- **輪郭をなぞるときは外周だけの 1 本のパス**を使う。マスごとの矩形を並べたパスを `stroke` すると、マスとマスの境目まで線が引かれる

#### 速さ

天面のテクスチャは素材あたり 2 枚（灰色・色つき）を焼いて使い回し、**ブロック 1 個の絵そのものもオフスクリーンに焼いて使い回す**。同じ形・同じ素材・同じ色なら 1 枚を共有するので、盤上に 20 個あっても焼くのは数枚。毎フレームやるのは絵を貼ることだけで、実測 60fps。

進行度の色はテクスチャを焼き直さない ―― 焼いたタイルの上に**色相だけを被せる**（`globalCompositeOperation = 'color'`）。ふつうの半透明で塗ると陰影まで薄まって木目も石の粒も潰れるが、これなら凹凸はそのまま残る。

### 消える瞬間を祝う ― 文字は出さない

「○個消し！」「◯コンボ」のような**字幕は一切出さない**。盤面の上に文字を置くと、いちばん見たいもの（次の一手）が隠れるうえ、読む時間だけテンポが落ちる。祝うのは**光と音**だけ。

| 行為 | 音 | 画 |
|---|---|---|
| ブロックを掴む・ボタンを押す | 乾いたウッドクリック（低め・小さめ） | 白い脈動するアウトライン |
| **押し出して滑る** | **動き出しの抵抗 ＋ 滑っているあいだ鳴り続ける摩擦** | 進行方向への残像 |
| **滑って壁にぶつかる** | **沈む低音の一撃（距離が長いほど低く・長く・強く）** | 進行方向へのつぶれ |
| 残り手数が減る手を指した | **75%（近づいただけなら 33%）で**、低く丸い和音 | 👍 のスタンプが 3 つ、跳ねて浮いて消える |
| 消える | **ウッドクリックの音程が連鎖ごとに階段を上がる** ＋ 薄いガラスが砕ける「シャラン」 | マスが光に開く → 破片が散る → ネオンの輪が広がる → 一瞬白む → 画面が揺れる |
| 3個以上まとめて消える | 直前に **0.1 秒止まる（タメ）** | 解放した瞬間に上の演出が一段強くなる |
| クリア | ウッドクリックの階段を駆け上がってガラスが散る | 星が 1 つずつ跳ねて出る |
| 動かせない方向 | 重い塊が動かず、押した力だけが返る詰まった音 | ブロックが小刻みに揺れて拒否（手数には数えない） |

連鎖の深さは**音程の階段・光の強さ・揺れの大きさ**が伝える。数字を読ませない。

### 解に近づくほど、画面があたたまる

**遊んでいる最中、いまの局面から解までの残り手数を厳密に知っています。**

レベルを読み込むとき、その盤面で到達できる配置を全部展開して、**すべての配置についてゴールまでの最短距離**を配ります（`src/exact.js` の `Explorer`。もともとレベルを焼くのに使っていた全探索を、そのまま実行時にも回している）。以後はどの局面でも表を 1 回引くだけで残り手数が出ます。

**配るために遊びを止めません。** 一気に回すと深い盤面では 0.5 秒以上のあいだ画面が固まるので、**フレームの余り（7ms、アニメーション中は 2ms）だけを使って少しずつ**配ります。レベルを開いた瞬間からふつうに指せて、時計も動きます ―― 配り終わるまでのあいだは、焼いてある手順と色つき 2 個の隙間で色をおおまかに動かし、表ができた時点で厳密な値に切り替わります（表示側がなめらかに追いつくので、切り替わりは段としては見えません）。

実測: 状態数 6千〜7万、配り終わるまで 30〜70 フレーム。読み込み自体は 16〜26ms で、そのあいだ 60fps を保ちます。

色はそれで動きます。**最短 40 手の盤面なら、色は 40 段。**

- 残り手数が **1 減れば、色が 1 段進む**
- 残り手数が **1 増えれば、色が 1 段戻る**

焼いてある解答と突き合わせるやり方では、こうはできません。**最短の道は 1 本ではない**ので、別の最短手順に乗り換えただけの手を「間違い」と誤解してしまう。距離を全部の配置に配ってあれば、プレイヤーがどこへ迷い込んでも、そこからの残り手数がそのまま引けます。

色の道すじは 冷たい藍 → 青 → 青緑 → 緑 → 琥珀 → 朱。盤面の受け皿は動かさず、**色つきブロックと背景**だけが動きます。1 手ぶんの変化は 0.5 秒ほどかけて渡すので、点滅ではなく景色として動きます。

**「あと◯手」とは絶対に出しません。**数字を出すと、盤面ではなく数字を見ながら遊ぶことになる。温度だけが変わるなら、視線を盤面から外さずに近さが伝わります。

> 全探索が使えない盤面（状態数が上限を超えるなど）では、焼いてある手順の線上にいるかと、色つき 2 個の隙間がどれだけ詰まったかで測ります。色の動きは粗くなりますが、遊べなくはなりません。

#### 背景は、下から満ちてくる

画面の後ろには**色つきブロックとまったく同じ色**を、うんと薄めて敷いています。背景だけ違う色にすると、2 つの色が画面で喧嘩する。

解に近づくほど、その色が**下から上へ満ちていきます**（進行度で止まり位置が上がる）。遠ざかれば下がる。色相と高さの両方が動くので、盤面を見ているだけで進み具合が視野の端に入ります。ブロックの色は手数の目盛りとして段で動きますが、背景は段に丸めません ―― 1 手ごとに画面全体がカクッと変わると落ち着かないので。

#### 👍 のスタンプ

同じ物差しで出ます。

| 出るとき | 確率 |
|---|---|
| **残り手数が減った**（その 1 手は最短手順のひとつだった） | **75%** |
| 残り手数は減らないが、色つき 2 個が**これまででいちばん近づいた** | **33%** |

毎回出すと壁紙になり、出なさすぎると気づかれない。だから間引いています。

### 音の作り

効果音は音源ファイルを持たず、WebAudio でその場で合成している（`src/audio.js`）。

いちばん手をかけているのは**ブロックを動かした音**で、そこだけ独立した設計になっている。軽い「カチッ」で済ませると盤面が紙のように感じられて、「壁を押しのけている」実感が消えるため。

- **押し出し（`slide`）** ― 動き出しの抵抗（低く短い一撃）＋ **滑走アニメとまったく同じ長さだけ鳴る摩擦**。ノイズをループさせ、ローパスの角を「開いて閉じる」ように動かすので、開くところが加速、閉じるところが減速に聴こえる。帯域を 600Hz 以下に抑えるのが要点 ―― 上が出ると砂や紙になり、石や木の塊には聴こえない
- **着地（`land`）** ― 5 層を重ねて「重さ」を作る。① 100Hz 台から 40Hz 台へ**落ちる**正弦波（一定の低音を鳴らしてもただの "ブーッ" にしかならない。落とすと質量が出る）② 塊の胴鳴り ③ 低く絞った接触ノイズ ④ **ごく短い中高域の一撃**（これが無いと低音がぼやけて、重いのではなく「こもった」音になる）⑤ 受け止めた板の余韻。距離が長いほど低く・長く・強くなる
- **ウッドクリック** ― 帯域を絞ったノイズの一撃（木を叩いた芯）＋ 上から落ちてくる基音（詰まった鳴り）＋ 4 倍音を少しだけ（マリンバの丸み）。掴む合図と UI ボタンに使う
- **グラスシャター** ― `[1, 2.41, 3.86, 5.62, 7.71, 9.94]` という**非整数倍**の部分音を、少しずつ遅らせて散らす。整数倍だと「鐘」に、非整数倍だと「ガラス」に聴こえる。上に高域ノイズ（破片）と帯域ノイズ（炭酸の泡）を重ねる
- **低いほめ音（`praise`）** ― F3 に完全五度を重ねただけの、低くて丸い和音。祝う音**ではない** ―― 祝ってしまうとクリアの音が軽くなるので、消去音（C6 まわり）よりずっと下に置いて重ならせない

ハプティクスは音を出す関数の中で一緒に鳴らしている。指と耳がずれない。着地の触覚は音と同じ形（短い前触れ → 間 → 長く重い本体）にしてある。

### 画面録画に音が乗る

iOS/Safari は **WebAudio だけを鳴らしていると音声セッションが「環境音」扱いのまま**で、消音スイッチで黙るうえ、**画面収録しても動画が無音になる**。

対策として、ほぼ無音の WAV を `<audio>` でループ再生し続けている。`<audio>` が鳴っているあいだセッションは「メディア再生」に上がり、同じセッションを共有する WebAudio の出力も消音スイッチを無視して鳴り、収録に乗る。

- 完全な 0 ではなく**最下位ビットだけを 22kHz で振っている**（人には聴こえず、「無音だから」と再生を止められることもない）
- OS に止められても復帰できるよう `pause` と `visibilitychange` を見張る
- 設定でサウンドを切ったらループも止める（鳴らさないのに音声セッションを占有しない）

## ホーム画面に追加する

追加すると **全画面で起動**し、**オフラインでも遊べます**。進行状況は端末に残ったままです。

| | やり方 |
|---|---|
| **iPhone / iPad** | Safari で開き、共有ボタン → 「ホーム画面に追加」。ホーム画面の**「ホーム画面に追加」ボタン**を押すと、この手順を図で出します |
| **Android** | Chrome が入れられると判断した時点で、ホーム画面に**「ホーム画面に追加」ボタン**が出ます。押すとそのままインストールできます |

すでに追加済みの端末では、このボタンは出ません（`display-mode: standalone` / `navigator.standalone` で判定）。

### 仕組み

- **`manifest.webmanifest`** ― `display: standalone` / `orientation: portrait` / 背景もテーマも `#ffffff`。パスはすべて相対（`./`）にしてあるので、GitHub Pages のようなサブディレクトリ配信でも壊れません
- **アイコン** ― 192 / 512 / マスカブル 512 / Apple Touch 180 の 4 枚。`tools/icons.mjs` が**依存パッケージ無しで** PNG を書き出します（`node:zlib` で固めた生のピクセル行が PNG の中身なので、これで足ります）。4 倍で描いてから平均縮小しているので角の丸みはなめらか。マスカブルは端末側で円などに切り抜かれるため、絵を中央 80% の安全領域に収めています
- **オフライン** ― `sw.js`（Service Worker）が
  - **ページ本体はネットワーク優先**（3 秒で諦めてキャッシュ）。オンラインなら必ず最新の HTML を取りに行くので、新しい版を出したときに取り残されません
  - **それ以外はキャッシュ優先**。`app.js` と `styles.css` は URL に内容ハッシュが付いている（`app.js?v=…`）ので、中身が変われば URL も変わる ―― 古い版を掴み続ける事故が構造的に起きません
  - インストール時に index.html を読んで、**そこに書かれているハッシュ付きアセットも一緒に先読み**します。ビルド側に一覧を持たせずに済みます
- **全画面での手触り** ― `viewport-fit=cover` ＋ `env(safe-area-inset-*)` でノッチとホームインジケータを避け、長押しの選択・コールアウトを止めています（読ませる文章だけは選択可能に戻す）

### 面白さの正体

ブロックは押した方向へ**壁か他のブロックにぶつかるまで**滑る。距離は選べない。だから「どこへ動かすか」ではなく **「どのブロックを、どの向きへ押すと、どこで止まるか」** を読むゲームになる。止める位置を作るには、先に別のブロックを置き直しておくしかない。

読む対象は 1 手先の「消える／消えない」ではなく、**「ここへ滑らせると、次にどこへ滑れるようになるか」** の連鎖です。滑って止まった直後は同じ方向へ進めないので、道のりは必ず曲がる ―― だから盤面を眺めていても道筋は見えず、**指を動かす前に頭の中で滑らせるしかない**。上のレベルはその連鎖が 110 段あります。

初期盤面に消せる手をひとつも残さないのは、この体験を最初の 1 手から始めさせるためです。目の前に「消える手」があると、人はまずそれを押してしまう。押せる手が無ければ、読むしかない。

## 「解ける盤面」を構造的に保証する

**盤面を作って解けるか確かめるのでも、解を作って盤面を導くのでもない。** ゴールの側から出発して、そこへ**戻れる配置だけ**を集めている。

```
S0（色つきが触れている＝ゴール）
  │ 前向き BFS：ここから指せる手を全部展開し、到達できる配置 R を列挙する
  ▼
R = { 配置 }
  │ R の中で「触れている配置」を全部まとめて距離 0 に置き、
  │ 逆向き BFS：1 手戻るごとに距離 1、2、3 … を配る
  ▼
dist : 配置 → ゴールまでの厳密な最短手数
```

初期盤面は `dist` から選ぶので、**「解けない盤面」は原理的に選ばれません**（距離が付いている＝ゴールに届く）。同時に、**その距離より短い解き方も存在しません**（幅優先探索の性質そのもの）。PAR と、★★★ の基準になる最短手順は、距離が 1 ずつ減る手をたどるだけで手に入ります。

> **前向き BFS はなぜ要るのか。** 逆向き探索を「S0 から到達できる配置 R」に閉じ込めるためです。R は S0 から辿れる配置の全体なので、`s ∈ R` なら `s` から行ける先も R に入ります（推移性）。だから R の中だけで距離を配っても、「R の外にもっと近いゴールがあって手数が縮む」ことは起こりません。この性質が無いと、出した手数が最短である保証が崩れます。

### 初期盤面からは何も消せない

採るのは距離 2 以上の配置だけなので、**初期盤面でどのブロックをどう動かしても何も消えません**（1 手で届くなら距離 1 です）。色つきは 1 組しかないので、消えるのは**いちばん最後の 1 手だけ** ―― 300 手のレベルなら **299 手ぶん滑らせ続けて、やっと消えます**。ここが読みの深さそのものです。

目の前に「消える手」があると、人はまずそれを押してしまう。押せる手が無ければ、読むしかない。

### 検算

焼き込む前に、`tools/levels.mjs` が**全在庫を実際に盤面へ組み直して手順どおりに指し**、本当にそこで消えるかを確かめます（通らないものは在庫から捨て、割合が高ければ書き出しを中止します）。`npm run verify` は焼き上がったデータに対して同じことをやり直し、統計を出します。

`npm test` にも同じ検算が入っていて、さらに**素朴な幅優先探索と距離を突き合わせる**テスト（`tests/exact.test.mjs`）で、全探索エンジンの出す「最短手数」が本当に最短であることを確かめています。

## ランキング ― レベル別・世界共通

クリアすると、その記録は**必ず**そのレベルのランキングに出る。「保存しますか？」は訊かない ―― 訊いてしまうと、押し忘れた回のぶんだけランキングが実態からずれて、「1位の人が本当に1位なのか」が誰にも分からなくなる。

そのぶん**名前だけは自分で打つ**。クリア直後に閉じられないシートが出て、名前を決めるまで先へ進めない。**一度決めれば、次からは自動でその名前が使われる**（設定シートからいつでも変えられる）。

順位は**手数の少ない順**。同着はタイムの短い順、それも同じなら先に出した方が上。同じ名前はその人のいちばん良い 1 件だけを残す ―― 1 人で上位が埋まると、何人が挑んだのかが分からなくなるため。

### サーバを立てる ― `npm run rank:deploy` だけ

ランキングのサーバは **`worker/` に入っている**（Cloudflare Workers）。立てるのに要るのは 2 コマンドで、うち 1 つは初回だけ。

```
npm run rank:login    # 初回だけ。ブラウザで Cloudflare にログインする
npm run rank:deploy   # これで上がる
npm run rank:log      # 届いた投稿と弾いた投稿を流し見する
```

**器を作るコマンドも、ID を貼り付ける作業も無い。** 記録の置き場は Durable Object（SQLite）で、`worker/wrangler.toml` に書いたクラス名だけで結びつくので、`deploy` の 1 回で器から表まで揃う。表は `worker/worker.js` の `constructor` が自分で作る。

D1 や KV を使わなかったのはこのため ―― どちらも「先に `create` して、出てきた ID を設定ファイルに貼る」手順が要る。ついでに KV の読み書き競合（読んで・足して・書く、のあいだに別の投稿が挟まると片方が消える）も避けられる。Durable Object はレベルごとに 1 つのインスタンスへ直列化されるので、同時にクリアされても記録は落ちない。

URL は `https://<name>.<アカウントのサブドメイン>.workers.dev/` になる。`name` は `worker/wrangler.toml` にあり、`src/config.js` の `RANKING_ENDPOINT` と揃えてある。**同じ `name` で上げ直せば URL は変わらないので、`src/config.js` は触らなくてよい。**

**空のあいだは、この端末の中だけにランキングを貯める。** 名前入力もクリア時の強制保存も順位表示もそのまま動き、画面には「この端末」と出る。あとから URL を差せば、同じ画面のまま「世界」に変わる。

サーバに求める約束ごとは 2 つだけ（`worker/` はこれを満たしている）。

```
GET  <URL>?level=12&limit=50
  -> { "entries": [ { "name":"…", "moves":18, "time":73, "stars":3, "at":1700000000000 }, … ] }
     手数の少ない順に並べて返す。素の配列を返してもよい

POST <URL>   Content-Type: application/json
  body { "level":12, "name":"…", "moves":18, "time":73, "stars":3 }
  -> { "ok":true, "rank":4, "entries":[ … ] }
     rank と entries は省略してよい（省略されたら改めて GET しに行く）
```

CORS（`Access-Control-Allow-Origin`）を許すことだけ忘れないこと。

サーバ側でも投稿は検分する（`worker/rules.mjs`）。**範囲外の値は丸めずに弾く** ―― 丸めて受け入れると「0 手クリア」が一覧の先頭に居座って誰にも消せなくなる。名前を整える関数はクライアントと同じものを読み込んでいるので、両者がずれようがない。同じ名前は主キーで 1 行に押さえてあり、並べ替えで間引くのではなく **そもそも 2 行目を作らせない**。

**通信が失敗しても記録は消えない。**投稿は必ず先に端末へ書いてから送るので、圏外でクリアしてもその回が無かったことにはならない。届かなかったときは画面にそう出る。

サーバーから来る名前は他人が打った文字列なので、一覧には必ず `textContent` で入れている（`innerHTML` に流すと、名前に書いた HTML がこちらの画面で動いてしまう）。

### 実装上のメモ

- **敗北条件を持たない。** 色つきは 1 組しかなく、消えるのは最後の 1 手だけなので、**消せる手が無いのが通常の局面**（どのレベルも初手はゼロ）。詰み判定そのものを外し、`戻す` と `やり直す` に任せている。
- **星は手数で付ける。** 基準の par が**厳密な最短手数**なので、★★★ は「最短ちょうど」という言い切れる達成になる。時間で測っていた時期もあったが、それは par が推定値でしかなかったころの折衷案だった ―― 最短が確定したいまは、手数のほうが素直に「読み切れたか」を表す。
- **星の意味が変わったので保存領域を分けた。** 記録の鍵を `slidepop.v4` から `v5` に上げ、引き継ぐのは到達レベルと設定だけにしている。秒で付けた星と手数で付けた星を混ぜると、数字の意味が食い違う。
- **状態は文字列にせず、バイト列のままハッシュ表へ入れる。** 全探索は 1 配置あたり数十本の後続を作るので、`Map<string>` にすると 1 配置につき数十本の文字列を確保することになり、そこが探索時間のほとんどを占めていた。専用のオープンアドレス法ハッシュ表（鍵はアンカー位置を並べた `Uint8Array`）に置き換えて、探索中の確保をゼロにしている。表とキューは使い回すので、何万回回してもメモリは増えない。
- **接触判定の世代印は、探索ごとに消す。** 「相手のマスに印を付けて隣を見る」判定を世代番号で使い回していたが、前回の印を持ち越すと**触れていない配置をゴールと読み違え**、距離が丸ごと狂う。実際に 120 レベル中 7 件が「手順どおりに指しても消えない」データになった。盤面は 64 マスしか無いので、探索の頭で毎回ゼロに戻すのがいちばん安い。
- **空きマスは「割合」ではなく「個数」で指定する。** 埋め率 86% のような指定だと端数のぶんだけ隙間が余り、そこがブロックの逃げ場になって手数が伸びない。空きがちょうど 3 マスになるまで敷き、ならなければその盤面ごと捨てている（捨てる率は半分ほどだが、1 枚あたり数ミリ秒なので安い）。
- **時計はゲーム画面を見ている間だけ進める。** シートを開いている間・タブが隠れている間・クリア後は止まる。`requestAnimationFrame` の `dt` をそのまま積むだけなので、タブが背面に回れば自然に止まる。表示の更新は秒が変わったときだけ DOM を触る。
- **色の並びは色相角ではなく ΔE で決める。** いまの盤面に出る色つきは 1 組だけだが、色パレットは「先頭から N 個取っても互いに遠い」ように組んである（同色ペアを複数置いていた頃の名残であり、その保証は残してある）。色相を等間隔に並べても遠くはならない ―― 緑は 90°〜160° がまとめて「緑」に見えるのに対し、赤〜橙は数十度でも別の色に見えるからだ。Lab 空間の距離で「すでに選んだどれからも遠い色」を順に選ぶ並びにしたところ、12 色での最小 ΔE が 15 → 31 になった（`HUES` は先頭から N 個取っても互いに離れているように並べてある）。
- **ブロックは外周だけを縁取る。** セル矩形の集合をそのまま stroke すると内部のセル境界にも線が出て、1 個のブロックが格子模様に見えてしまう。外周の辺と外側の角だけを集めた Path2D を別に作って使っている。
- **配信物は 1 本に束ねる。** `index.html` と `src/*.js` を別々に配信すると、ブラウザが「新しい HTML ＋ 古い JS」を組み合わせてしまうことがある（GitHub Pages はどちらも短い max-age で配信し、Safari は JS を長く保持する）。実際にそれで盤面が真っ白になった。`app.js?v=<内容ハッシュ>` に束ねれば HTML と JS が食い違いようがなく、`file://` でも動く。生成物が古いままにならないよう、`npm test` が最新かどうかを検査する。
- **画面収録が無音にならないようにする。** iOS/Safari は WebAudio だけだと音声セッションが「環境音」のままで、消音スイッチで黙り、画面収録にも乗らない。ほぼ無音の WAV を `<audio>` でループさせてセッションを「メディア再生」に上げている（詳細は上の節）。
- **操作音は `pointerdown` で鳴らす。** `click` を待つと指の動きから 1 テンポ遅れる。`document` に 1 つだけ委譲リスナーを置き、`button` と `.switch` を押した瞬間にウッドクリックを鳴らす ―― ここが音の解錠地点も兼ねているので、ホーム画面のボタンを押した時点で iOS の音が開く。
- **ガラスの照り返しは `background` に敷く。** `::before` のオーバーレイで重ねると、テキストノードだけのボタン（`<button>レベル一覧</button>`）では膜が文字の上に乗ってしまう。`background` なら backdrop-filter の上・内容の下に必ず入る。
- **アイコンも依存パッケージ無しで作る。** PNG は「zlib で固めた生のピクセル行」なので、`node:zlib` と CRC32 が書ければそれで足りる（`tools/icons.mjs`）。生成物は `npm test` が最新かどうか検査する。
- **Service Worker にビルドの一覧を持たせない。** インストール時に index.html を読んで `app.js?v=…` / `styles.css?v=…` を正規表現で拾い、それを先読みする。ビルド側と二重管理にならない。
- **`roundRect` は自前でも用意する。** Safari 16.4 未満に無いので、無ければ `CanvasRenderingContext2D` と `Path2D` に足している。
